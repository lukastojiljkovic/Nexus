# PRD 02 — Dashboard & Widgets (DASH)

**Status:** draft 2026-07-05. Inputs: raw-spec §3, `docs/research/design-system.md`
(chart kit, views), `docs/research/onboarding-ux.md` (pre-population),
founder ideas: countdown widgets, summary, urgent items.

## 1. Purpose

The dashboard is the app's home: one glance answers "šta mi je danas bitno?"
It aggregates across every enabled module — obligations, urgencies,
reminders, progress, recents — through user-arranged widgets. It is also the
first proof of personalization after onboarding.

## 2. User stories

- As a user, I want today's obligations and urgent items in one place, so
  that I don't tour five modules every morning.
- As a student, I want exam countdowns and today's study plan up front
  during exam season, so that priorities stay visible.
- As a tinkerer, I want to add, remove, resize, and arrange widgets, so that
  the home screen matches how I think.
- As a returning user, I want quick actions and recent items, so that I
  resume work in one click.

## 3. User experience & flows

Default layout generated by ONB per persona. Edit mode (long-press / "Edit
dashboard") enters a grid with drag-drop, resize handles, add-widget gallery
(grouped by module; only enabled modules' widgets appear), and per-widget
settings (period, filters). Read mode is dense, calm, keyboard-navigable;
every widget deep-links into its module. Widgets render skeletons while
loading and honest empty states ("Nema obaveza danas 🎉").

## 4. Functional requirements

- **DASH-001 (M)** The dashboard shall be a user-arrangeable grid of widgets
  with add/remove/resize/reorder in an explicit edit mode.
- **DASH-002 (M)** Widget availability shall follow feature flags: a module's
  widgets appear in the gallery only when the module is enabled; disabling a
  module hides (not deletes) its widgets and their configuration.
- **DASH-003 (M)** Core widget set at v1: Today/Agenda (tasks + calendar
  merged), Urgent & overdue, Reminders, Countdown (exams/events/deadlines),
  Quick actions (new task/note/capture), Recent items (notes/documents),
  Study today (plan + review queue), Stats mini-charts (per chart kit),
  Habit streaks (if HABIT on), Budget snapshot (if FIN on).
- **DASH-004 (M)** Each widget shall be configurable (period: today/
  week/month/year/custom where applicable; source filters, e.g. which task
  lists; size presets).
- **DASH-005 (M)** Every widget shall deep-link to the underlying module
  view of the same data.
- **DASH-006 (M)** The dashboard shall respect profile separation: personal
  and business profiles have independent dashboards; the calendar-derived
  widgets show the shared overlay with origin markers (decision #4).
- **DASH-007 (M)** Initial layout shall come from ONB's declarative mapping;
  ONB re-runs propose changes via diff preview, never silent rearrangement.
- **DASH-008 (M)** Multiple named dashboards (e.g. "Fokus", "Pregled") shall
  be supported in v1 (founder decision 2026-07-05); they appear in the
  navigation sidebar grouped with separators between categories.
- **DASH-009 (S)** A compact "day strip" header (date, weather-free, next
  event, focus timer status) should be available.
- **DASH-010 (C)** Widget gallery may include third-party/plugin widgets
  post-v1 (PLUG).

## 5. Options & settings

Edit mode; per-widget config; dashboard tabs (S); density (comfortable/
compact — design system); reset to ONB-generated layout.

## 6. Integrations

Every module contributes widgets through a widget contract (name, sizes,
config schema, data query, deep link) — the contract is part of this PRD so
modules implement it uniformly. ONB (initial layout, starter widgets);
NTF (reminder counts); SRCH (dashboard is not a search surface; quick
actions open capture instead).

## 7. Edge cases & error states

- No enabled modules beyond Essentials → default layout still meaningful.
- Widget whose module data is empty → onboarding-pattern empty state inside
  the widget, one action.
- Very many widgets → vertical scroll allowed; performance budget: initial
  dashboard render < 300 ms with 12 widgets on reference hardware (per
  design-system performance budgets).
- Small windows / narrow web viewport → responsive reflow to single column,
  order preserved.
- A widget erroring (e.g. corrupted config) → isolated error card with
  "reset widget", never a blank dashboard.

## 8. Acceptance criteria (key)

- Adding, resizing, moving, configuring, and removing each core widget works
  with mouse and keyboard alone.
- Disabling FIT removes its widgets from gallery and dashboard; re-enabling
  restores prior widget configuration.
- Business profile shows its own dashboard; calendar widget marks event
  origin distinctly in both profiles.
- Dashboard renders within budget with 12 widgets and 2 years of data.
