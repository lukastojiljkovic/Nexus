# ADR-119 — The translator runs NLLB-200: three model packs, a process of its own, a sentence at a time

**Status:** accepted (2026-10-23). **Owner:** the 2.5 run. Replaces the Bergamot sentence
translator, which no ADR recorded; the word dictionary and the phrasebook (ADR-091's
`dictionary-sr-en`) are not touched. Uses [ADR-091](091-content-packs.md),
[ADR-105](105-voice.md) and [ADR-117](117-assistant-acts-through-the-page.md).

## 1. What it replaces, and why

Up to 2.1.1 a sentence was translated by Bergamot (`@browsermt/bergamot-translator`) in a
renderer worker, from one of six `translate-*` packs: Serbian, Croatian and Bosnian to and from
English, one direction per pack (Mozilla's models, MPL-2.0). Six directions were the whole of
what it could do, and every new pair would have been another model from a project that has
none for most languages.

Luka asked for a translator that is "not hardcoded any more", between all the languages a local
model can read, "bukvalno kao lokalni Google Translate". NLLB-200 (Meta AI) is one model for
202 languages in any direction, and `@huggingface/transformers` already runs ONNX models in this
app for speech (ADR-105). So the translator runs NLLB-200 through it, and Bergamot, its worker,
its dependency and the six packs leave the app.

## 2. Three model packs, one at a time

`nllb-600m`, `nllb-1.3b` and `nllb-3.3b` are `kind: "model"` packs (ADR-091), each the model in
ONNX quantized to `q8` with its tokenizer. The user installs any of them. With more than one
installed, the Translate tab offers a choice and uses the one chosen, else the smallest
installed. Measured by the builder on 2026-10-22:

| Pack | Model | Size |
| --- | --- | ---: |
| `nllb-600m` | `facebook/nllb-200-distilled-600M`, Xenova's ONNX repackaged | 911 962 632 B |
| `nllb-1.3b` | `facebook/nllb-200-distilled-1.3B`, converted here | 1 940 515 828 B |
| `nllb-3.3b` | `facebook/nllb-200-3.3B`, converted here | 4 466 791 113 B |

No maintained ONNX conversion of the 1.3B or the 3.3B existed, so both were converted with the
Transformers.js conversion script (`--quantize --modes q8`). The 3.3B decoder came out as one
weight file of 2 665 885 696 B, past the 2 GiB a release asset holds, and
`scripts/packs/nllb/split-external-data.py` rewrites it into two files under 1.9 GB with the
bytes unchanged. Two rules follow, both pinned by tests:

- **The chunk count is read from the pack's files** (`main/nllb/externalData.ts`), not written
  down per size, and passed as `use_external_data_format` only when there are chunks.
- **A weight file is copied into place, never hard-linked**: ONNX Runtime refuses external data
  with more than one link.

The conversion, the split and the per-file sizes are in [`docs/packs/nllb.md`](../../packs/nllb.md).

## 3. A process of its own, loaded on the first translation

NLLB runs in an Electron utility process (`main/nllb/`), on the voice host's arrangement: nothing
starts until the first translation, every message is checked against `protocol.ts` in both
directions, and the folder a request names is one main resolved from an installed,
signature-verified pack. Remote models are off on every load and there is no cache directory.

It is not the voice worker's process, because that one holds one model at a time and a page that
dictates and translates would load a gigabyte model again for every sentence. Nor is it the
renderer, where Bergamot ran: ONNX Runtime's native build runs in main's children, and a model
of several gigabytes does not belong in the window's process.

The worker ends fifteen minutes after the last translation (`IDLE_UNLOAD_MS`, the assistant's own
default), which gives the model's memory back; the next translation starts it again.

## 4. A sentence at a time, as the user types

NLLB-200 was trained on single sentences, and a paragraph handed to it whole comes back
shortened. Main cuts the text with `Intl.Segmenter`, which knows the sentence ends of every
script the 202 languages use, and keeps each sentence's trailing whitespace so the translation
keeps the paragraphs. The worker answers each sentence as it is done.

The page translates after a short pause in typing. The kit has no push channel, so a translation
is a job the page polls, one at a time: a new text cancels the one before it, and the worker
reads the `cancel` at once and stops before the next sentence. The sentence being decoded
finishes, because ONNX Runtime has no point inside a run at which it can stop.

## 5. The languages

The table (`shared/languages.ts`, 202 rows) is generated by `scripts/translator/languages.mjs`
from NLLB's own tokenizer, with each code's BCP 47 tag and a name from `Intl.DisplayNames`, or
from FLORES-200 where ICU has none or two codes share a tag. The pickers name each language in
the interface language and search by that name, the English name or the code. The source is
guessed with `franc` (MIT) until the user chooses one.

**Serbian is `srp_Cyrl` only**: NLLB has no Latin Serbian. Latin input is converted to Cyrillic
before it is sent, and Cyrillic output can be shown in Latin.

## 6. No voice

The plan gave the translator speech in and out (Whisper, and MMS-TTS voices converted for every
language the two share). Luka dropped it on 2026-10-22 ("zajebi da translate ima glas
nebitno"); the voice commits were reverted and the language table has no speech columns.

## 7. The licence

All three models are CC BY-NC 4.0, quoted from each model's README in
`scripts/packs/nllb/sources.json`, and the builder refuses a pack whose page does not state it.
Nexus is free with no ads and no paid tier, so a non-commercial model ships as a pack with its
licence named and its attribution shown, as the voice pack's MMS model already does.

## 8. The assistant

`translator.translate` takes an NLLB code or a language tag on each side, with detection when the
source is absent, and needs one NLLB pack installed. It opens the Translator page with the text
and an action (ADR-117) rather than translating in the tool: the model runs on the page's
request, and the tool's answer tells the assistant it cannot read the result, so it does not
translate the text itself.

## 9. Consequences

- The six `translate-*` packs stay in the v1 catalogue, so 2.1.1 and older keep installing them;
  2.5 neither lists nor reads them.
- `check-egress` loses Bergamot's allowlist entry, and the licence notices lose its package.
- A translation needs a pack of at least 911 962 632 B (the 600M), where a Bergamot direction was
  one small model.
