### The renderer ships minified; the main process deliberately does not (2026-09-26)

electron-vite leaves the renderer at `minify: false`, and STATUS §4.1 had it as
„a decision rather than a default to flip": no sourcemap ships, so a minified
stack trace names `a3`, not a function. Measured before deciding, with a third
option beside the two obvious ones:

| Built renderer (bytes) | Unminified | Minified, names kept | **Minified** |
| --- | ---: | ---: | ---: |
| Startup chunk | 2 331 423 | 1 620 436 | **1 283 478** |
| All renderer JS | 21 950 581 | 16 807 337 | **13 152 582** |
| Stylesheet linked at startup | 728 734 | 295 212 | **295 212** |
| All CSS | 873 395 | 439 826 | **439 826** |

**The decision turned on who reads a stack trace, and in the renderer nobody
does.** The application menu is `null`, so the shipped app opens no DevTools;
nothing in the tree reads `.stack`; no renderer console is forwarded to a log.
A renderer defect is diagnosed in `pnpm dev`, which Vite never minifies. Keeping
names would have cost 337 KB of the startup chunk to protect a reader that does
not exist. **The main process is the opposite case and stays unminified:** an
uncaught exception there is shown by Electron's own dialog, stack included, and
a screenshot of that dialog is the one bug report this product can actually
receive. The reasoning is in `electron.vite.config.ts` beside the line.

**Verified by looking, not by trusting a transformation.** Gates, `SMOKE OK`
(which opens every page and every tool from the built renderer), and a full
sweep of the minified build: `SHOTS OK — 2839 frames, 0 findings`. Compared
pixel by pixel with the previous full sweep, about four frames in ten differ —
the same share as between the two sweeps compared earlier the same day — the
median differing frame by 11–16 pixels (a caret), and every frame that differs
by more than 2 000 pixels has a cause that is not this change: „Tabla" drawing its board at the second and third sizes (the fix
below), clock-dependent study and ledger data, `electronics-part`'s moving
subject, and „Alatke" landing on its first tool since the toolkit split. The
last was confirmed directly: the „Alatke" scene alone, minified and unminified
from one tree, gives the same eleven frames, and the few pixels that differ
between them differ equally between two unminified runs.

**No startup time is claimed.** Bytes are what was measured; the roadmap's gate
on performance claims still stands.

### „Tabla" erased a board when it was left too soon — found by a sweep, fixed (2026-09-26)

**Found sideways.** Comparing full screenshot sweeps for the route split, the
demo board „Arhitektura sistema" was drawn in every `min` frame and an empty
canvas in every `default` and `wide` frame — on the 1.3.0 code as much as on the
split, so not the split's doing. Bisecting the scene list narrowed it to „leave
the canvas for another page, come back": a partial run of the canvas scenes
alone, which never leaves the page, drew the board at both sizes. A probe then
drove the built app over the DevTools protocol and read the STORED scene before
and after: 14 elements, then 0. It was not a rendering problem. The drawing was
gone from disk.

**The mechanism** is [[DC-144]]: the page flushed a pending save from an
unmount cleanup by asking the editor for the scene, after Excalidraw's
`componentWillUnmount` had already replaced its scene with an empty one. The
load itself counts as a change, so the gesture needed no edit at all — open a
board, click another module within 800 ms. Three gestures on the 1.3.0 build,
three empty boards: open and leave after 300 ms; change the stroke width and
leave after 100 ms; and the same with a wait, on a board the first gesture had
already emptied.

**The fix is a module with no editor in it.** `canvasAutosave.ts` decides when
to write and writes what `onChange` was handed, so no path exists that reads the
editor late. Written test-first (nine cases: the defect itself; opened-and-closed
writes nothing; an edit is written once, after the delay; a pan is not a write;
a switch files the edit under the board it was made on, whether or not anyone
flushed; a failed write stays owed; one edit is never sent twice while in
flight). The same three gestures on the fixed build: 14 elements kept, the
stroke-width edit kept, the second edit kept. Three paths that used to DROP an
edit — creating a board, deleting one, restoring one — flush first now, and a
write that lands after a switch no longer puts „Sačuvano" on the board it did
not write to. One that FAILS after a switch is said in the page's own notice
instead of nowhere, since the board it failed for took its save line with it.

**And it is gated where it can be seen.** A geometric audit cannot tell an empty
board from a drawn one, and a unit test cannot tear a real Excalidraw down, so
the gate is `smoke`: the page walk seeds the demo boards before it starts, leaves
„Tabla" the moment it is shown, and fails if any board has fewer elements
afterwards. Its negative control, the 1.3.0 `CanvasPage` in the current build:
`SMOKE FAIL: page walk: leaving „Tabla“ lost drawing — „Arhitektura sistema“
14 → 0`.

**What it means for the founder's own data** is in STATUS §1: the installed
1.3.0 carries this, likely every installer since the canvas shipped does, and a
board that already emptied can only come back from an archive made before.

**The comparison that found it, for the record.** Two full sweeps on the same
date, the 1.3.0 code and the split build, 2 839 frames each: the median frame
that differs differs by 14 pixels (an input's caret, the rail's one-pixel edge),
and every large difference was traced to data that moves with the clock — a
flashcard that came due between the runs, „Nedavno" in the tools drawer — except
one, `electronics-part`, which selects whatever part is first in the DOM and
chose a different one in each of three runs. That is recorded in STATUS §4.1
rather than fixed here.

### The tools drawer fetches a toolkit when one of its tools is opened (2026-09-26)

„Stručne alatke" are both `ToolsPage`, and `proToolSurfaces.tsx` imported every

| Built renderer (bytes) | Before | After |
| --- | ---: | ---: |
| Opening either drawer (its chunk and what it imports, beyond startup) | 3 239 250 | **54 987** |
| Then opening a tool from „Gradnja" | — | +162 705 |
| Then opening a tool from „Event" (the largest toolkit) | — | +226 052 |

**How.** A file's tools have to be known before the file is loaded, and they are:
the registrations name them. `PRO_TOOL_GROUPS` in `shared/modules.ts` gives the
per-subject arrays that already existed a name each, and `PRO_TOOLS` is now
derived from it rather than written beside it. `proToolSurfaces.tsx` maps every
registration to a `lazy()` component that shares its file's one fetch, so the
map's keys are exactly what they were and every consumer — the host, the
surface-map test in `modules.test.ts` — reads it unchanged. The developer
toolkit is nine files split by `category`, which the registrations carry.
`ToolsPage` reads the open tool through `useDeferredValue`, `App`'s own device
one level down: the rail moves on the click, the tool being left stays until the
next one's file has arrived, and a boundary of the surface's own means a
toolkit arriving never suspends the page around it.

**What keeps it honest.** The registrations now make a claim about each file —
which surfaces it exports — and `proToolSurfaces.test.ts` loads every file and
holds it to exactly that list, and holds the files together to every
professional registration once. The smoke walk opens every tool of both drawers
— 11 and 322, counted from the registry and asserted — from the built renderer;
with `gradnja`'s chunk removed from `out/` it fails naming „Uglovi i direkcioni
ugao“. The whole run, pages and tools, takes about eighteen seconds.

### Every page is its own chunk, and Excalidraw left the startup path (2026-09-26)

STATUS §4.1's route-splitting and Excalidraw items, done as one piece because
the second is a consequence of the first. `App.tsx` imported all sixteen pages
statically, so the renderer was one chunk that every session parsed before its
first paint: Excalidraw, KaTeX, the note editor, every professional tool and the
developer drawer, to show a dashboard.

| Built renderer (bytes) | Before | After |
| --- | ---: | ---: |
| Startup chunk (`index-*.js`) | 11 261 086 | **2 330 636** |
| Startup + the dashboard route, everything it imports | 11 261 086 | **2 455 576** |
| All renderer JS | 21 905 958 | 21 919 923 |
| Stylesheet linked at startup | 873 395 | **728 734** |

The total barely moves, which is the point: nothing was removed, it was put
where it is used. The canvas route is Excalidraw (1 679 165 bytes, in a chunk
Rollup names after one of Excalidraw's own modules, `percentages-*`) and its
stylesheet (144 661 — the two stylesheets add up to the old one exactly);
„Učenje" carries KaTeX (661 438); the tools route is 3 239 250. **No startup time is
claimed** — the roadmap's standing gate says a performance claim waits for a
harness that measures it, and bytes are what was measured.

**How it is built.** `routes.tsx` is the lazy table, one `lazy()` per page,
each adapting the page's named export so no page grew a `default`. `App` reads
the page through `useDeferredValue`: the sidebar and the title strip move on
the click, while the pane keeps the page being left on screen until the next
one's chunk has arrived, so a first visit does not blank the pane to a
skeleton. That also decides the boundary's shape — `PageSlot` is never keyed by
page, because a boundary mounted fresh per page has nothing to keep on screen
and would blink on every first visit. The skeleton is therefore seen once, for
the first page after unlock. `PageSlot` is also an error boundary, which is new:
a chunk that cannot be read used to be impossible, and an uncaught rejection
inside `lazy` unmounts the whole root — sidebar and all. It now costs one page,
with a sentence (`strings.app.pageError*`). A page that throws while rendering
is caught by the same boundary, which is a behaviour change worth recording:
before, that too blanked the window.

**Two things would have defeated it silently, and both were found by reading
the output rather than trusting the source.**

- `PRIV_LOCKED_EVENT` was a constant exported by `PrivPage.tsx`, imported by
  `App` (which dispatches it) and by `NotesPage` (which listens). One constant
  would have kept „Privatno" in the startup chunk. It lives in `privEvents.ts`
  now.
- `Onboarding` writes one welcome note per profile, ever, through
  `parseMarkdownNote` and `buildNoteUpdate` — and its static import of the two
  was the only reason Yjs and the markdown importer, about 270 kB, were in the
  startup chunk after the pages had left. It reaches them through
  `import("./markdownNote.js")` now. The target has to be a module of the app's
  own: `@nexus/core` is imported statically by the shell, so a dynamic import of
  the package resolves to the startup chunk and moves nothing.

`routes.test.ts` is what keeps both true. It walks the static value-import graph
from `main.tsx` in source — `import type` is not an edge — and fails if it
reaches any module the renderer loads with `import()`, if any `…Page.tsx` file
is not loaded lazily (derived from the directory, so tomorrow's page is covered
the day it is written), or if the startup path imports Excalidraw, KaTeX, TipTap,
ProseMirror or Yjs directly. Proved against a planted regression — a static
`CanvasPage` import and a `katex` import in `TitleBar.tsx` — which it named.

**A trap that was suspected, measured, and is not one.** Vite loads a lazy
chunk through a helper that appends `<link rel="modulepreload">` for the chunks
it depends on and `<link rel="stylesheet">` for its CSS, with `crossOrigin = ""`
set in JavaScript — the attribute `rendererHardening` strips from `index.html`
on the stated grounds that a `file://` origin refuses a CORS-mode fetch. The
helper waits for the stylesheets and rethrows on failure, so the canvas, whose
chunk carries Excalidraw's CSS, looked like a page that would open under
`pnpm dev` and never in the installer. The first version of this work therefore
turned both off (`cssCodeSplit: false`, `modulePreload: false`). **Then it was
measured, and it holds up in neither direction:** with Vite's defaults the page
walk below passes, the canvas opens, and a run with `ELECTRON_ENABLE_LOGGING`
shows no preload or CORS error at all — Electron 44 serves those links from
`file://`. The canvas frames are pixel-identical with one stylesheet and with
two (every canvas scene, both sizes, both themes). So the defaults stay, and
they are better: Excalidraw's 144 661 bytes of CSS now arrive with the canvas
instead of at startup. The override would have been a fix for a failure that
does not exist, justified by a sentence nobody had checked — and the sentence
it leaned on, `rendererHardening`'s own, is now known to be at least
incomplete; it was not re-examined here.

**The smoke run now opens every page.** `runSmokePageWalk` names the smoke
profile (the shell does not exist for an unnamed one, so every earlier smoke run
rendered the questionnaire), switches every module on, reloads, and clicks each
sidebar row and the search page, failing unless the pane shows that page, not
busy and not a skeleton, with the boundary's failure state absent. It is the
only check that loads the chunks from `file://` under the production CSP, and it
has a side effect nothing before it had: each page MOUNTS against a real
database once per smoke run. It also watches the pane with a
`MutationObserver` and fails if the skeleton appears at any navigation after the
first page, which is the one claim of this design a reader cannot check by
looking at the code. Both negative controls were run: the canvas chunk removed
from `out/` gives `SMOKE FAIL: page walk: canvas failed to draw`, and
`useDeferredValue` replaced by the raw id gives `the pane blanked to the
skeleton 15 time(s)` — one per page opened cold. With it, zero.

**The screenshot sweep waits for the page it asked for.** A click on a sidebar
row can now land before the page does, and a frame taken then is the previous
page filed under the new name — a frame that photographs as an ordinary page.
`settle()` waits until the pane is not `aria-busy` and no skeleton is present,
and says so on stderr if a page takes longer than eight seconds; it lives in
`settle()` rather than `openModule` because a scene's `prepare` and a dashboard
card navigate too. The whole sweep was run on this build, in a Linux container
(Xvfb, so no maximised frame and none of Windows' fonts — its findings are not
comparable with the founder's runs, only with each other): 2 839 frames, 0
findings, and the eight-second warning never printed.

### Every package tells the bundler it has no side effects (2026-09-26)

STATUS §4.1's first item, and the note on it was right that the measurement was
the work: `"sideEffects"` was absent from every `package.json`, so Rollup kept any
module it could not prove inert — and a module-scope `new Map(...)`,
`new TextEncoder()` or `utf8("nexus/…")` is something it cannot prove. The seven
source packages now declare `false`; `@nexus/ui` and `@nexus/tokens` declare
`["**/*.css"]`, because each exports a stylesheet that is imported for nothing
but its effect.

| Output | Before | After |
| --- | ---: | ---: |
| `apps/web` bundle | 632 106 | **246 175** (−61 %) |
| `apps/gallery` bundle | 664 814 | **279 217** (−58 %) |
| desktop main | 3 308 275 | 3 298 784 |
| desktop renderer, eager chunk | 11 261 086 | 11 259 478 |

The web shell was carrying most of `@nexus/core` — the FIT catalogues'
`catalogue.json` and `exercises.json` alone were about 330 kB of it, and now no
food name appears in the bundle at all — for a page that reads a handful of
manifests. The desktop
barely moved, and that is the finding rather than a disappointment: the renderer
genuinely reaches most of `core`, so the eager chunk is not shrunk by telling the
bundler what is unused. It is shrunk by not loading what is not yet on screen,
which is the next item.

**How „nothing broke" was established,** since a wrong claim here fails only in
a built product and every suite reads source. What the declaration removed was
listed from the sourcemaps rather than inferred from the byte counts: three
modules left main (`tasks/quickAddDate.ts`, `tools/units.ts`,
`sync-crypto/src/pairing.ts`) and four left the renderer
(`imex/archiveContainer.ts`, `imex/csvImport.ts`, `order/rank.ts`,
`priv/privEnvelope.ts`), each of whose exports its bundle does not use and each of
whose module-scope code only builds its own constants. The web shell and the
gallery were served from both builds and rendered in Chromium: **the same
`#root` HTML, byte for byte** (132 and 2 311 nodes, identical hashes), no console
error. The main process took `smoke`.

**The apps do not declare it, and that was measured too.** Adding it to all three
changed every output by exactly zero bytes — an app's own modules are all reached
for their exports — while it would license the bundler to drop
`CanvasPage.tsx`'s `import "./excalidrawAssets.js"`, the side-effect import that
tells Excalidraw where its fonts are. A declaration with no gain and one
identified way to break the canvas is not made.

**The claim is now checked, not remembered** — `scripts/package-side-effects.test.mjs`.
A wrong `sideEffects: false` is invisible to Vitest (no tree-shaking), to `tsc`
and to the dev server, so it would ship. The test requires every package to
declare the field, allows nothing but stylesheet globs in a list, and walks every
shipped module of every declaring member for the two shapes the bundler would
now delete: an import made for its effect alone, and a module-scope statement
that reaches past its own module (a global write, a call into an import, a push
into someone else's registry). `pro/tekst.ts`'s two top-level loops that fill its
own transliteration tables are local and pass; `excalidrawAssets.ts` is a fixture
that must fail, which is also what makes the apps' abstention a rule rather than
a note. It prints no total: each declaring member must have contributed modules
to the walk, which cannot go stale the way a count would.

#### A file that walked the repository three times

CI went red on `pnpm test`, in `check-copy.test.mjs`, with

```
FAIL scripts/check-copy.test.mjs > the live tree > finds nothing unread…
Error: Test timed out in 30000ms.
```

A message that names neither the gate's subject nor the cause. The cause was
arithmetic the file had been carrying since it was written: it walked the live
tree **three times** — once for the census, and twice inside the verdict's
test, because `scanRepo()` IS `findings(repoCopyLeaves())` and the call beside
it walked the tree again. One walk measures **7.3 s** against this tree's
~15 900 leaves, so 22 of the file's 35 seconds were the same work on the same
unchanged tree. Locally that passed: 14.7 s against the 30 s budget. On the
runner, where all thirty-three script files walk the repository at once, it did
not.

**And this suite's budget had already been raised once for exactly this.** 5 s
→ 30 s, with the reasoning written into `vitest.scripts.config.mjs`: every gate
there walks the whole repository, `check:quotes` timed out at 5 s in a full run
on 2026-09-03, and a CI runner with fewer cores is the same failure with less
warning. A third raise would have been the same answer twice.

The fix is a memo — one walk per file — and the better half is not the speed.
The census and the verdict now describe the **same** walk, so „found nothing"
and „looked at less than it should" cannot come from two different readings of
the tree, and the floors that prove the walk looked are asserted over the
object the verdict was computed from. Measured after: the file is **8.9 s** and
its heaviest test is the one walk it needs. Every file was then timed rather
than this one assumed: the next-slowest is 4.4 s against the same 30 s, so the
worst headroom in the suite went from about 2× to about 3.4×. Recorded as a
recurrence of [[DC-35]].

B and C are the same commit and the same tree, and they differ by 62 bytes.
So the build is **not byte-reproducible** — a fact worth having measured rather
than assumed, because the figure was about to be written down as a property of
the commit. A size or a hash identifies an artefact here, never a revision; the
digest that matters is the one `latest.yml` carries beside the file that was
actually built. Nothing depends on it yet, and the day the update feed exists,
it will.

### Circuits become the tenth thing Ctrl+K can find (2026-09-22, `dad4946`)

ELEC shipped without a `SearchKind`, and STATUS.md recorded the gap as a
statement about the work rather than a defect: *„circuits are not reachable from
Ctrl+K — that needs a migration and a backfill, not a component."* That reading
held. A tenth kind is not a chip added to a list; it is six declarations that
must agree, and the compiler can check five of them.

#### The sixth place

`SearchKind` (a union and an array), `SEARCH_KIND_PREFIXES` (the Serbian
aliases), `KIND_PRIOR` (the ranking rung), `SEARCH_KIND_MODULE` (which module
switches the kind off), the migration — and `SEARCH_SOURCE_VIEWS` in
`searchStore.ts`, which nothing can check, because it is a list of view NAMES as
strings. Migration 070's own doc comment says all six out loud, and the comment
is the only instrument that does: a view renamed without its entry here leaves
`rebuildSearchIndex` iterating a name that does not exist, in a code path no
test drives by default.

#### The half a trigger cannot do

The search tables are filled by `<table>_search_ai/_au/_ad` triggers, so a new
kind is a projection view plus a triple of triggers. That covers every future
write and not one row already on disk — and every circuit a user owns was
written before the kind did, so without the backfill at the end of the migration
their own workbench is invisible to their own search until each circuit is
renamed. The migration ends with one `INSERT … SELECT … FROM
search_source_circuit`, which is also why the view exists: the trigger triple
and the backfill read the SAME projection, so the fold rules cannot differ
between a row written in 2025 and one written tomorrow. The test opens a
database at 69, writes a circuit, migrates, and asserts the row is findable —
which is the only way that half is visible at all.

The rung went between a document and a subject, and the ladder was re-spaced
rather than re-ordered: nine kinds had filled `0.01…0.09` with no room between
any two, so ten kinds share the same span at a finer step. Documented in
`searchRanking.ts` as a re-spacing, because the diff looks like a re-ranking.

#### Three findings, all closed rather than noted

`nx_fold` is a SQL function the index cannot be written without, and twenty test
helpers registered it by hand while the twenty-first — written when no migration
above 64 used it — did not. Migration 070 made that false and the failure
surfaced as `SqliteError: no such function: nx_fold` from five tests about
migration 065. [[DC-140]]: a copy can be counted, a missing line cannot.
`prepareConnection` is that preparation's one home now.

`SearchKind` was declared twice, in `@nexus/core` and again on the IPC wire,
under a comment saying the copy „cannot drift silently". It could, in exactly
one direction — wire widened, core not — which is the direction nobody reaches
by accident. [[DC-141]]: the sentence vouching for the duplication is what
stopped anyone checking it. It is imported now, and the tenth kind proved it:
widening core alone compiled everywhere.

And `onSearchResult`'s switch over the kind had nine arms and no `default`, so
the tenth would have fallen out of the statement — a hit the user can see in the
palette and cannot open. [[DC-142]]: exhaustiveness is a property of an
expression position; a switch used for its effects is a statement. It ends in
`assertNever` now.

#### The swatch, and what the cascade change was waiting for

`.note__swatch--none` and `.canv__swatch` were six identical declarations on two
pages, differing only in the order they were written, and the canvas copy was
also applied to its COLOUR tiles, where nothing inside the box reads it. Both
are `.nx-swatch--none` in `@nexus/ui` now (`86ef2b9`) — the third piece of that
control to move there, after the box and its 24px floor. It had waited in
STATUS.md as a cascade change to look at rather than reason about, and looking
at it was three surfaces and 21 frames with zero findings.

#### Verified

Typecheck 13/13, lint 14/14, every package's suite, build 4/4, all twenty-seven
static gates, `SMOKE OK`, and two partial sweeps read by eye: the palette's chip
row ends in „Kola" and the search page's facet line reads „Kola 3".

### The marker on the arm that had something in it (2026-09-22, `a405247`)

The item this closes was recorded as a shape with the photography already done
around it: on 2026-09-07 `renderList` and `renderGrid` were given
`data-nx-content` so the sweep would measure them, and both of those elements are
returned only when there ARE entries — so on the empty page the marker was not in
the document at all. What made it worth doing was that the note recorded the RULE
rather than the symptom: **the marker belongs on the box the module is FOR, not
on the arm where that box has something in it.**

#### What the emptiness actually cost

Nothing, on the day it was written, and that is the honest ledger. The empty arm
draws no `StatBand`, so `hollow-fixture` had no figure to contradict and
`below-fold` had no region to measure — both rules were silent, and silent is
exactly what a correct page looks like. What was missing was the page's ability
to be SEEN misbehaving: the day a figure lands in that arm, or the filters grow
tall enough to push the landing down, the audit's answer would still have been
the same green line. A claim that exists only in the states where the page is
full is a claim that is absent exactly where a page is likeliest to be wrong.

#### The fix, and why the populator had to stay outside

`.doc__rows` is one box, written once in each arm: the list on one path, the grid
on another, either empty state on the third. The band, the `FileSpace` graphic
and the cap advice stay outside it — and that is not tidiness. `hollow-fixture`
asks whether a region holds nothing but an empty state, and a region that
CONTAINS the band can never be that one, so marking a wrapper around the figures
and the rows together would have bought `below-fold` at the price of the other
rule. The box declares a copy of `.doc`'s own column, so the arms sit precisely
where they sat as direct children of it.

#### The blast radius: two more pages, and one that must not change

Grepping the construct rather than the file found the shape twice more. STUDIJA
carried the marker on `.study__subjects`, drawn only when a subject exists — so
the landing a profile with nothing in it actually opens, the one a new user sees
first, was the unmeasured one; the same class is now on the empty arm's stand-in,
which is what that box IS in that arm. NAVIKE is the case that defines the
boundary rather than an instance of it: its marker is on „Danas“, behind
`!noHabits`, and with no habits the page drops its whole middle and answers in
the register's landing. That box exists in both states and is deliberately
unmarked — it is the module's archive and it is legitimately below the fold — and
nothing there is unprotected, because `below-fold` has no subject to measure on a
page that has none, and the band is guarded on the very condition the marker is
guarded on, so `hollow-fixture` has no figure to contradict either.

**So the rule is not „mark every empty state". It is that a region the page draws
in every state keeps its marker in every state, and that a state which abandons
the region is a DECISION — which has to be written down**, because „deliberate"
and „forgotten" leave the same three lines missing. That decision now lives in
`contentMarkers.test.ts`, in the block above the census it qualifies.

#### The census, and the number that did not move

`contentMarkers.test.ts` holds one number per page, and DOKUMENTI's stayed at 2:
two row shapes inside one arm became one box written in two arms. The number
counts WRITINGS, so it cannot report a hole — the reason string beside it is the
claim, and the count only says that somebody edited that line on purpose. That is
[[DC-138]]'s lesson one layer over, and it is why the fix carries as much comment
as code: the entry that replaces this one will be written by somebody reading
those comments, and the only thing they cannot re-derive is which of the two
shapes was intended.

#### What was verified, and what the verification cannot reach

The full set before the commit: typecheck 13/13, lint 14/14, every suite, build
4/4, `SMOKE OK` and all twenty-six static gates. Then the camera — a PARTIAL run
(`NEXUS_SHOTS_SCENES=files,study`, three sizes, both themes) rather than the full
sweep, because the change reaches exactly two pages and the full pass is two
hours of frames about code this diff does not touch. 66 frames, 0 findings, and
the two pages read by eye against the design rules: DOKUMENTI's list still starts
under the `FileSpace` bars with its band above them, its grid still tiles from the
same top edge, and UČENJE's cards are unmoved under the folded „Pregled". A
partial run is a different kind of run and says so — no pruning, no questionnaire,
findings in `report.partial.md` — which is [[DC-138]]'s rule applied to the run
itself.

**And it cannot photograph the thing that was fixed.** The sweep's profile has
five files and a subject, so both pages are photographed POPULATED: the empty arms
this change is about are unreachable from the harness, exactly as they were
unreachable before it. That is not a gap the sweep leaves — it is the reason the
census in `contentMarkers.test.ts` exists, and the reason the fix is structural
enough to state in a test rather than illustrated by a PNG.

### E6 — the app that may start a process, and the two rules that keep it honest (2026-09-22, `1ab31fe` … `9b6db0d`)

The last slice of ADR-085, and the one that changes what the product IS rather
than what it can show. Until this landed the shipped application had exactly one
capability boundary and it was the NETWORK: off by default, structurally out of
reach with cloud off, guarded by `check:egress` and asserted at the packet layer
by `main/net/offline.ts`, so a user who never turned sync on was in a product
that could not reach anything. Starting a process is the second boundary, and it
is the sharper of the two — a network call leaves the machine and a process runs
ON it, with the user's own rights.

That is what [DEV-007](../deviations.md) authorises, over four mitigations rather
than a default, and the whole arc is those four turned into shapes rather than
promises.

#### The command line is never data, and the two rules that do the work

The table is `packages/core/src/electronics/runner.ts`, and it is the file the
gate exists to keep true. It is in `@nexus/core` rather than beside the spawn for
the reason a `.nexus.zip` is an ordinary shareable artefact: in the threat that
matters the circuit on the other side of an import was written by whoever sent the
file, so a runner that assembled a command out of circuit data would be a
general-purpose execution primitive reachable from an import. Every command is a
literal in that file. The circuit contributes ONE value — the workspace path,
which Nexus derives — and it arrives as a single argv element, never as text
spliced into a string.

`check:runner` is the twenty-sixth gate and it is shaped like `check:egress`,
because it is the same kind of question asked about a new boundary. Five rules:
`child-process` is one file plus its two tests; `shell`, `exec-family` and
`spawn-literal` are exempted for NOBODY, asserted at import by
`assertNoSecurityExemptions()` — the shortest path from a red gate to a green one
is to add a rule id to the map, and that path here would paper over the deviation
itself. The fifth, `toolchain-name`, is vocabulary rather than security, and its
word boundaries are load-bearing in a way worth keeping: the match is
case-insensitive because a capital letter must not defeat a rule and the copy
says „Docker" while the table says `docker`, but under that match `colcon` is also
the first six characters of `colConcentration` and `colContribution`, two Serbian
table-column keys. A boundary-free version reports those four lines and nothing
else — four findings no honest exemption covers, in a gate whose output is then a
fifth noise, which is worse than not having it because it also carries the
authority of having run.

**The interaction between two rules is what makes the mitigation structural, and
it reads like a coincidence and is not one.** The file allowed to import
`node:child_process` is NOT allowed to contain a toolchain word. So the program it
spawns cannot be a literal it wrote — it can only be `argv[0]` of a plan that came
out of the table. The one file permitted to spawn is the one file that may not
know what it is spawning. That cost a real repair rather than a comment: the
profile ids ARE the tools' own names, so `elecRunner.ts` could not ask „is this
the docker profile?" without becoming a finding. `buildCommand` therefore puts the
container's NAME on the plan and the caller asks whether there IS one —
`plan.container !== null` — which is the only question it actually needed.

The `exec-family` rule needed a negative lookbehind, and that one is worth the
sentence: `re.exec(text)` is a regular expression and not a process, `runner.ts`
alone calls it twice, and the repair a reader reaches for when a gate cries wolf
is not a narrower gate — it is an exemption, and then a second one.

#### Off by default, one run at a time, and a consent that is a row

`elec_settings` (migration 069) is one row per profile with `runner_enabled`
defaulting to 0, and three CHECKs that make the interesting states
unrepresentable: a remembered choice on a runner that is off, a distribution
under any choice but WSL, and — the one the whole feature is for — **enabled with
no recorded consent**. The `IS` in the second CHECK is not a slip for `=`: `'wsl'
= NULL` evaluates to NULL, a CHECK that evaluates to NULL PASSES, and the `=`
form would admit exactly the row it is written to refuse.

The consent screen prints the LITERAL command, and it can, because the screen and
the start call one function: `buildCommand` is pure and the renderer imports
`@nexus/core` for its own preview, so what the user reads and what runs are the
same string. That is also why the plan carries `pullsImage` on the plan rather
than letting a caller infer it from the profile — „the Docker profile pulls an
image from a registry" is the one network operation in the module and the consent
copy owes the user that sentence.

**The consent cannot be forged by an archive, and that took checking rather than
believing.** `elec_settings` is named nowhere in the import or export path, and it
is in the restore's exemption ledger for the reason that ledger exists: a consent
carried to another machine by an archive would be somebody else's yes, and a
desktop that never gave one would run builds because another one did. A
repo-wide search for the table returns the store, the migration and two comments
— which is the arrangement the exemption records.

Turning the runner off clears the choice and the distribution in the SAME write,
because the store refuses the alternative and a half-applied write is worse than
a refused one. The first `consentedAt` is the one kept: the column's meaning is
„when this person agreed", one historical fact, not the last time a toggle moved.

#### Five defects the last mile turned up, and one of them was mine

- **The runner may not be pointed at a workspace it did not write.** `writeWorkspace`
  wipes and rewrites the directory before every run, and `start` re-checks
  containment at the last moment rather than only where the path was derived —
  the two are separate moments, and the interval between them is where a symlink
  swap would live.
- **A `distro-unknown` refusal was removed rather than implemented.** A
  distribution that has since been removed from the machine fails at the run, in
  `wsl.exe`'s own words, and main could only beat that sentence by re-probing —
  which is a process, on the plan path, for a message the tool already writes.
- **A settings write that omitted a field rather than clearing it.** `choice()`
  wrote `{choice: id}` and left `distro` alone, so switching away from WSL kept
  the old distribution beside a profile that cannot carry one: the store refused
  the write, and the user saw a message about a field nobody had touched. It now
  writes `distro` on every path — including the null one — and the reason is
  recorded at the site, because „omit what did not change" is the natural thing
  for the next caller to do. The same shape was hunted across all six settings
  stores afterwards: one other site depends on a field it does not name
  (`backupSettingsStore.setSchedule` needs `folderPath` and `passphraseWrapped`
  once `enabled` is true) and is safe only because nothing can clear either, while
  the renderer's disabled checkbox is not the gate. That is recorded as a
  conditional, not a clean bill.
- **A select whose „none" option could never succeed.** The WSL distribution
  picker's placeholder carries `value=""`, and `<select>` spells „nothing
  selected" that way — but the contract spells it `null`, and main reads any other
  string as a NAME. So `asDistro("")` threw on the one option that exists to UNDO
  the field, every time. It now translates at the edge. The blast radius is every
  `<option value="">` in the renderer: fifteen sites, and the ones that are
  correct are correct for a reason — a FILTER whose `""` means „all" is a plain
  string and not a null-able field.
- **One refusal reason that meant two things.** `no-choice` covered both „no
  profile chosen" and „WSL chosen, no distribution under it", and the sentence
  written for the first — „Nijedan profil nije izabran" — is simply false beside a
  radio that is visibly selected. This REVERSES a decision recorded in the test
  that asserted it („one reason for both, because there is one consequence: no
  target, so no command"): the consequence is one, but the reason is not read by a
  machine, it is read by a person as a sentence, and the axis a refusal has to be
  split on is the REPAIR. Picking a distribution out of a list is a different
  action from picking a profile, and the state is not a corner — choosing WSL
  stores `distro: null` until one is picked, so it is the ordinary state between
  two clicks.

#### What was designed against, measured rather than assumed

- **`docker version` and not `docker --version`.** Measured on a machine with
  Docker Desktop installed and its engine stopped: `--version` exits 0 with the
  client's version, `version` exits 1 and says it cannot reach the API. A probe
  that answered „installed" would give a panel that says the profile is ready and a
  run that fails on a pipe error, which reads as a Nexus bug.
- **The child's environment drops `NEXUS_*`, `ELECTRON_*`, `DOCKER_*` and
  `WSLENV`, for two different reasons.** The first two are this app's own, because
  a `process.env` copied wholesale is how the runner would be handed a passcode or
  a database path by accident. The second two are REDIRECTIONS: `DOCKER_CONTEXT`
  pointing at another machine would make every path in the argv, and every answer
  about „is the container still there", be about a computer the user is not
  sitting at. The command line is fixed by source; the environment is not.
- **The WSL profile runs an INTERACTIVE shell (`-ic`), which is a widening of the
  first mitigation and is what the feature needs.** ROS's documented setup appends
  `source /opt/ros/<distro>/setup.bash` to `~/.bashrc`; Ubuntu's `.bashrc` returns
  early when `$-` has no `i`; and a login shell reports `$-` as `hBc`. So `-lc`
  would report a CORRECTLY configured distribution as unusable while the user's own
  terminal worked — both answers „right", and the app's the useless one. The
  residual is stated plainly rather than smoothed: „Nexus runs `colcon build`" is
  really „Nexus runs `colcon build` in the shell the user configured". It is the
  amendment to DEV-007.
- **The Docker image is pinned by INDEX DIGEST**, and the reasoning is
  determinism rather than trust: a tag is mutable, so the thing executed on the
  user's machine would be chosen by Docker Hub rather than by this file — but the
  contents are still OSRF's build, and „digest" must not be read as „verified".
  The index rather than a per-platform digest is what makes the pin usable on more
  than one machine shape. There is deliberately no fallback to the tag, because a
  pin that falls back is a pin a later helpful edit removes.

#### The half a green suite cannot stand for

`dispose()` on quit kills the process and issues the container removal, and a
crash takes that away: the runner's state is in memory only, so the next launch
shows `idle` with no last outcome and a surviving container is not looked for.
`docker run --rm` bounds it — the container removes itself when `colcon build`
finishes on its own — so the question is only whether the app should say so, and
it is in §5 as a trade rather than a decision.

And no round has happened against a real toolchain on this machine: nothing here
has Docker Desktop running with an image, or a WSL distribution carrying ROS.
What is verified is the argv the plan produces, the way main drives it, and the
command the user is shown being the command that runs. What a live engine then
does with that argv is exactly the half a test cannot stand in for.

#### Also in this pass

- **The screenshot sweep photographs the CONSENT state and never enables it.**
  Enabling writes a consent row, and a harness that wrote one on the founder's own
  machine, on his behalf, would be granting the permission DEV-007 exists to
  require. So `electronics-runner` is a scene whose subject is the screen the user
  meets first — unlike every other scene here, whose job is to show the feature
  working.
- **The sweep's own coverage claim was prose, and the run had been failing it in
  silence.** `CLAUDE.md` describes the sweep as „three window sizes plus
  maximised", and `win.maximize()` is a REQUEST to the window manager rather than
  a setter: one of four runs on 2026-09-03 wrote it, both of the two before
  `5f2331f` refused, the four runs immediately after it wrote it, and the run of
  this pass refused again. A capture that lands by luck is a capture nothing may
  depend on, and no ratio is stated here because sweeps ran in between whose
  outcomes were never recorded. A
  refusal takes no frame and says so on stderr — the honest answer — but the
  headline then read `SHOTS OK — 2 839 frames, 0 findings` exactly as a clean
  run's does, and the headline is the only part a reader takes away. That is
  [[DC-138]]: **a summary computed from what the run PRODUCED cannot report what
  it FAILED to produce**, because a bucket that produced no frames contributes
  nothing to count. The fix moves the claim off the prose and onto the artefact —
  `missingCoverage` reads the frames themselves and names the absent size on the
  headline and in `report.md` — and it is deliberately quiet about a subset run,
  which never claimed that coverage; a warning that fired on every forty-second
  subset run is exactly the noise [[DC-124]] records being switched off.
- **`scripts/run-lock.mjs` went from one lock per verb to ONE LOCK FOR THE WHOLE
  HARNESS.** Per-verb locks read as though the resource were covered and were not:
  `--smoke`, `--shots` and `--demo` build into the same `out/` and then run the
  same binary out of it, so a `smoke` and a `shots` starting together corrupt the
  half of the run neither owns alone. The kind travels inside the lock now, so the
  refusal can still name what is in the way.
- **A migration header and a store doc each claimed a mirror that was not there.**
  `030-dashboard-settings` said three CHECKs each mirroring a store rule; there
  are four, and the two FUSED ones — the background triple is all-null or all-set
  — are the schema's alone, because the store validates the three columns
  independently. `elecSettingsStore.refuse` said „the same rules and no extras"
  while enforcing a length cap the migration does not check, and that asymmetry is
  deliberate rather than missed: adding it to 069 would have meant editing a
  migration whose version is already recorded, which does not re-run and would
  therefore protect nothing on any database that had it.

### A gate that had to shrink to nothing, and a sandbox two runs shared (2026-09-22)

Four commits and a finished sweep. Two of the four close work that had been
written and held back; the other two answer defects found by the sweep that was
supposed to be verifying something else. The thread is that each one was a
question about REACH — what an instrument actually covers, as opposed to what it
says it covers.

#### A citation that resolves, to the wrong thing (DC-132, `37bc7ee`)

`packages/sync-transport/src/signal.ts` fixes the realtime topic namespace and
cited „migration 006" for it. This repository has two migration series and both
number from 001: the local SQLite schema, which is at 068, and the server's,
which has thirteen files and carries no 006 at all. The policies the sentence was
about are in the server's 004, and the only 006 in the tree is the local
flashcards table — so the citation resolved, to a table about Anki decks, in a
file about sync.

Nothing could see it: a prose citation has no type, no import and no call site,
and the number it names is real. The fix is to cite the FILE, because only one
series has timestamps for names, and the enforcement is `check:migrations`, scoped
to `supabase/` where there is one series and nothing to exempt. It checks that
each file declares its number once, that no two declare the same, that the
numbers run forwards against the filenames, that every citation under `supabase/`
resolves, and that the hand-kept tree listing in `supabase/README.md` is
complete — it had already lost four of thirteen migrations by omission.

The gate found a live instance the day it was written, in the README paragraph
explaining the numbering, which itself said „Migration 006". That is the evidence
it is not vacuous, and it is also why the ungatestable half is stated in the
gate's own header rather than left for a reader to find: in `packages/` there are
two series and no directory-scoped rule can say which one a citation means, since
`packages/sync/src/push.ts` cites the server while its sibling `collections.ts`
cites the local schema.

#### The demo profile's files were rows pointing at nothing (`69744aa`)

`seedDemoProfile` wrote rows and no bytes. Every attachment in the demo profile
was therefore an index row naming a blob nothing had stored: unopenable,
unviewable, unsearchable, in a profile whose entire purpose is to show the
product working. It now takes a `DemoAttachmentIo` — somewhere to put bytes —
and writes each file through the same content-addressed encrypted store
`attach:pick-files` uses, quoting the plaintext SHA-256 back into the row. The
seed is `async` as a consequence, and `seedDemoAttachments` runs last of the
seeders, because the file it writes hangs off a row written by an earlier one.

`--shots` and `--demo` additionally put the private section into the state a real
one is in once somebody has set it up, which nothing else can do: the wrap is
derived from the ACCOUNT PASSCODE, and main keeps no copy of a passcode — it
verifies one and forgets it. The section is locked again immediately, because
setup adopts the DEK with a five-minute idle timer and the frame would otherwise
depend on how long the sweep had been running. `regenerateKit: false`, because a
minted kit would be a code nobody has seen and the card would report one that
opens nothing. `runShots` takes that passcode as a `ShotFixtures` argument rather
than reading it from `shots/`, so the one copy of it stays where the account was
created.

#### Twenty-four leaves, and a gate registered because they are gone (DC-133, `276b11a`)

`check:copy` walks the copy table and the markup and asks, of every leaf,
whether anything reads it. The class it enforces cannot be seen by anything else
in the tree: an unread leaf typechecks, lints, passes `check:strings`, carries no
colour and no token, and photographs as nothing at all — because it is not on
screen. `waveValuesHint` is what the class costs: the only sentence anywhere
saying that a list of readings is separated by semicolons, in a dialog that never
drew it, so `0, 1,5` was one reading and no error.

It found 24, and they were not one defect. Four wanted RENDERING:
`onboarding.packsNoChoice` (what happens if you choose no pack, on the screen that
asks you to choose one, which is the only place it can be said),
`devtools.design.gradient.stops` (a heading over a section that had none), and
`fitness.training.start.error` and `fitness.training.set.actionError` — both
written for exactly the failures they describe, both unreachable because
`fitTrainingError` had a default that answered for every caller. That default is
gone: `fallback` is a required parameter, so the compiler is now the census of
who has to decide, and all nine call sites name their own sentence. The other
twenty wanted DELETING — copy left behind by a screen that was rewritten,
`study.title` chief among them, saying „Predmeti" for a page whose rail and header
both say „Učenje" — and their doc comments went with them rather than being left
stacked above their neighbours.

The gate is allowlist-free, because the rule is a statement about what a leaf is
REACHED BY. A leaf is read when something NAMES its path, when a key is computed
against an INDEXED subtree, when a member resolves through a dotted literal a
registry carries, or when a subtree is HANDED to a call the walk cannot follow —

#### One run at a time, and a startup that can fail out loud (DC-134, DC-135, `a44adc3`)

The sweep that was meant to verify two dozen field conversions found something
else. Two `shots` runs on one machine resolve the same sandbox and each wipe it on

processes starting in the same millisecond cannot both win it, carrying the pid so

first must not delete the second's lock. `launch.mjs` now runs the build itself,

wrong for exactly that reason — three verbs share one `out/` — which is the sort
of thing that only shows up when the sentence is written down. `app.whenReady()`
now has the `.catch` that makes the silent half-start impossible rather than
absent, and the sandbox wipe refuses by name, saying which sandbox and why.

### The row that aligned its boxes (2026-09-09)

Three commits, and the middle one is the joint: a batch of labels that was
supposed to be routine turned four forms visibly ragged, and the reason is a
rule nothing in the tree had ever stated.

**Step 1 of [[DC-120]] is closed — all fourteen fields whose only name was one
a screen reader could hear.** Twelve now draw a name: TASK's „Rok", „Počinje"

**Then the calendar's form went ragged, and so had three others.** A labelled

The rule that was actually wrong is not „four stylesheets copied a
declaration". It is **„a row picks its alignment once"**: `center` was correct
on the day each was written, because while every child of a row is one box tall
`center`, `end` and `start` draw the same picture. A change three files away,
entirely right in itself, altered a child's HEIGHT and with it the meaning of a
property in a stylesheet nobody touched. Alignment is only a free choice while
the children agree about their shape. [[DC-122]].

**`check:rows` is the twenty-first static gate**, and it has to read both sides
because neither carries the discriminator: the stylesheet cannot say what is in
the row — `center` is right on the fifty-odd toolbars, chip rows and segmented
groups that are not this — and the markup cannot say how the row is laid out.
So it fires only where a container's direct children mix the two shapes AND its
class declares a flex row, which is a statement about what a row CONTAINS and
therefore needs no exemption list. Fragments are transparent, which is correct
rather than an oversight: CAL's two `type="time"` fields live inside
`{!allDay && (<>…</>)}` and are laid out by `.cal__form`. It takes `end` and
`flex-end` both — they compute identically in a flex container, and demanding
one spelling would have been a preference wearing a defect's clothes, worth
eleven edits to eleven already-correct rows.

Twenty containers in the tree mix the two shapes; fifteen declare a flex row;
four were centred and eleven already said `flex-end`.

**THE GATE WAS SILENT ON THE VERY DEFECT IT WAS WRITTEN FOR**, and finding out
why is worth more than the gate. Flipping `.cal__form` back to `center`
produced nothing. The shared lexer in `scripts/jsx-elements.mjs` was reading
TypeScript type arguments as elements: `ChangeEvent<HTMLInputElement>` is not
self-closing and is never closed, so it sat on the nesting stack and swallowed
every following sibling as its child. `check:controls` and `check:tiers` ask
for one specific tag and had never met it — `input` and `select` are not
generic type names — so the bug had been latent since the lexer was written and
became reachable the first time a caller walked EVERY tag. **A shared scanner
is only as correct as its most demanding caller**, and a gate reporting nothing
is indistinguishable from a clean tree ([[DC-36]]'s shape).

The discriminator is the character before the `<`: a generic's closes up
against the name it parameterises, JSX's never does. Its cost is written down
as a test rather than left to be rediscovered — `xx<p />` is now skipped,
which is a real false negative for JSX text (`<p>foo<b>bar</b>`) and the right
trade here by measurement: every one of the eleven places an identifier abuts a
`<` in the renderer is `typeof` or `keyof`, not markup.

**The suite now asks the question the gate cannot.** `scanRepo()` returning an
empty list is both the correct answer and the answer a broken walk gives, so

name only a screen reader can hear is the entire subject of the rule.

### A red job that named the wrong thing, and a caption that named the same thing twice (2026-09-07)

Two unrelated defects, worked in the same pass because the first arrived while
the second was waiting on verification.

**`main` was red, and the message pointed away from the cause.** The `database`
job failed at `196cd9a` on „The edge functions, against the running stack" —
`mint failed: ""`, ten cancelled tests — after passing on both PRs that produced
that merge and on the merge before it. The temptation is to call that a flake.
The log says otherwise: the failing call was the FIRST request any Edge Function
received in the job, it came back 503 with an *empty* body, and the twenty-four
calls after it all succeeded.

The empty body is the whole diagnosis. Every path through these functions
answers in JSON, and their own 503 is `unavailable()` carrying
`{"error":"unavailable"}` — so an empty-bodied 503 never reached any function's
code. `config.toml` sets `policy = "oneshot"`: the edge runtime builds a worker
per request, and the first one for a given function also fetches its module
graph over the network. Unbounded work, unrelated to what either suite tests,
and it had won the race every previous run.

So the rule that was wrong is not about the runtime. **The suites treated „a
function can be served" as an assumption**, which made the request that
discovered otherwise an assertion about a mint — and that is why the failure
sent the reader to the function, the migration and the auth server, none of
which were involved. A precondition asserted through reports as whatever it was
asserted through.

`ready.mjs` states it positively: the runtime is ready when the FUNCTION
answers. A GET carrying the anon key, which every endpoint refuses on its first
line with `bad_request` before reading a header, touching the database or
provisioning anything — so the probe proves the module graph loaded and the
handler ran, creates no state, and cannot be confused with the gateway's own
JSON refusal. Explicitly not „retry on 5xx", which would swallow a server
running degraded.

It went into the suites rather than into `ci.yml` because a developer running
`pnpm test:live` against a freshly started stack hits the identical trap, and a
workflow step covers only CI's reading of it.

**The part worth keeping is what the mutations showed.** The helper's own tests
were written to prove the rule fires, and three mutations were run by hand: a
gate that never waits failed five of them, a partial one failed one — and the
careless version, „retry on anything ≥ 500", passed *all nine*. It is the
version somebody writes. Two more tests were needed before it failed: the
platform's own 401 and a 404 must not read as ready either, because the test
that matters is not „the body parsed" or „it is not a 5xx" but „this exact pair
came from the handler". A wait loop is the shape of code that looks right while
doing nothing, and a suite that only asserts the tree is clean cannot tell the
two apart.

A second test then reads every live suite and requires the wait to be the first
statement of its `before` hook. A helper nothing obliges you to call is one the
next suite will not call, and `pair-complete` — the third function, with no live
suite yet — is the file that will forget. Not a twenty-first gate: one directory
of two files is too small a reachability set to be worth a script plus a CI step
to keep in step with it.

**The blast radius reaches the product, and is deliberately left open.**
`packages/sync-transport` has no 5xx handling and no retry anywhere, so the same
cold boot against hosted Supabase would reach the desktop as `refused`,
`reason: "unknown"`, `httpStatus: 503` — on the user's very first „turn on
sync", which is the call most likely to meet a boot. Recorded in STATUS rather
than fixed: sync is on hold, and the honest answer to step 4 of the doctrine is
that first-contact latency was never designed for in that layer at all. That is
a decision about the transport's error model, not a loop around one call site.
Recorded as DC-118.

**The second defect was in one card of the electronics bench.** The simulation's
readout captioned every value with a noun from `strings…sim.units`, keyed by
`SimUnit`. Two of the three units did not need one: `formatSimValue` already
renders „3,3 V" and „100 %", so „napon" said volts twice — and on the percent
channel „radni ciklus" sat under a number three rows below the FIELD
„Radni ciklus (%)", which shows the square wave's own duty rather than what the
pin drives at this tick. Two different numbers, both right, one label, one card.

`satisfies Record<SimUnit, string>` is what hid it. It asks whether every key
has been filled in, which is a question about the type; the question that
mattered — does this key need a value at all — is a question about the
formatter, and the type system's answer looked like the answer to both. A total
record makes a missing entry impossible and an unnecessary one invisible.

The record is now `Record<SimUnit, string | null>`: still total, so a new unit
must still be made to choose, but „the number already says it" is now one of the
choices. The test asks the oracle instead of restating it — a unit is captioned
exactly when `formatSimValue(unit, 1)` still reads `1` — and iterating the
record iterates every unit. Photographed across the three sim scenes in both
themes at three sizes: 24 frames, 0 findings. Recorded as DC-119.

**Both are green on `main` at `943d6a9`** — `database` and `verify` pass, the
live suite 24/24, and the `device-register` suite now takes 7.4 s where the
failing run took 3.3 s. The difference is the boot it now waits for. The full

### The ladder that was only ever prose (2026-09-07)

One commit, `1923642`, on the next carried-over item: „the app has never had a
layer scale." True, and the item also named one concrete hazard — which turned
out not to exist.

**What the tree actually held.** Twenty-two `z-index` declarations over eleven
files, seven distinct positive values, each chosen where it was written. The
interesting part is not that they were numbers; it is what the numbers meant.
`1` was „a header pinned over its rows" in seven places and „the lower of two
pinned ranks" in an eighth. `2` was „the ghost being dragged" in two files and
„a pinned header" in two others. Two boxes that never meet can hold the same
number for opposite reasons and nothing is wrong until the day they meet.

A stacking order is a property of the whole document — the language says so,
since two positioned boxes in one stacking context rank against each other
whatever files they were written in — and this one was being decided a file at
a time. Every other cross-cutting value here had already been through that
conversion: the type tier last week, `layout`'s rail widths before it. Stacking
was the axis nobody converted, because it is invisible until two things
overlap.

**The tell was a documentation smell.** Five comments in `notes.css` alone
restated the entire ladder in prose — „over `.note__find`'s sticky 3 and under
every portalled panel (50–70)". A comment that has to name four other files'
values is doing a type system's job in English, and English is the one artifact
in this repository that nothing can contradict. Both of the failure modes that
implies had already happened: one comment still cited a layer `40` that nothing
had carried for months, and one described a hazard that had never been real.

**So `--nx-layer-*`**, running `under` · `ground` · `figure` · `raised` ·
`docked` · `drawer-scrim` · `drawer` · `panel` · `overlay` · `dialog` · `menu`,
adopted at all twenty-two sites. Two names may resolve to the same number on
purpose — a pinned header and a figure over its ground are both 1 — because a
token names an intent, and moving one intent later must not silently drag the
other with it. Every swap is value-identical, and that was checked rather than
asserted: the diff was read back mechanically, resolving each new token to the
integer it replaced, twenty-two for twenty-two.

**`check:layers` needs no exemption list, and that is the reusable part.** The
tempting rule is „a positive z-index must be a token", with `0`, `-1` and
`auto` carved out. Instead the scale was given names for the two cases that are
not ladder positions at all — `ground` is „behind a sibling, lifting nothing",
`under` is „behind my host's children, in front of its background" — after
which the rule reads „every z-index is `auto` or one `var(--nx-layer-*)`" and
there is nothing left to exempt. Widening the vocabulary removed the need for
the list. An allowlist is how a gate stops being read; the cheapest one is the
one the design makes unnecessary.

It reads TS as well as CSS, because `useAnchoredPosition` sets inline styles on
exactly the boxes at the top of this ladder, and a CSS-only rule would close
the class in stylesheets while leaving it open one file away. An AST pass
rather than a grep, so that READING `style.zIndex` — which `shots/audit.ts`
does deliberately, on every positioned box it measures — is a different node
shape and not a finding.

And it checks the scale itself, which is the half a spelling rule misses
entirely: all twenty-two call sites name layers, so all twenty-two would go on
passing if `dialog` were edited to sit under `drawer`. The declaration order in
`global.json` is the stacking order, so it is asserted to be strictly
increasing — the file states the ladder and is checked against itself. Both
halves were made to fail on injected defects before being kept, because the
gate went green on its first execution and a gate that reports nothing looks
exactly like a gate that finds nothing.

**The hazard the item named was never real**, and it is the better finding.
`notes.css` had carried it for a month, carefully hedged: the three typed-name
confirmations `NoteOrganizer` renders would be trapped in the drawer's stacking
context (5) rather than reaching the dialog layer (60). The reasoning read the
JSX, where `<TypedConfirmDialog>` does sit inside the drawer's returned tree.
It portals to `document.body`. A portal is precisely the construct that makes
the React tree and the DOM tree disagree about who contains whom, and a
stacking context is a DOM relationship.

The dates settle it. `NoteOrganizer` adopted the portalled component on
2026-08-06; the hazard was written down on 2026-08-07, in a commit whose whole
purpose was „write down what the notes drawer's z-index costs". It was false
the day it was authored, by one day, and then survived the fifteen-file
stylesheet split verbatim. Nothing in the repository could catch it — a comment
compiles, lints, and photographs as nothing — and it was written in the
register of somebody who has thought carefully, which is exactly what stops a
reader checking. It even ended with the right recommendation. The comment now
says what is true, including that it was wrong and why.

### Thirty-three rules that were each correct (2026-09-07)

Three commits — `2057212`, `41b0ae6`, `ffbdd4e` — on one item from the
carried-over list, which turned out to be describing the wrong thing.

**The item said „Podešavanja".** It had been recorded on 2026-08-21 as a page

The dead band is `packages/ui`. `.nx-page-header` laid its children out with

sigil, so any header WITHOUT a subtitle opened with sixty pixels of nothing
under the title. Counting: eighteen pages set a sigil, four set a subtitle. The
broken shape was the default and the four correct pages were the exception —
which is the opposite of what the item said, and the reason the fix is one
declaration in a shared component rather than a patch on one page. `center` is
right for both cases: a title-plus-subtitle block centred against its sigil is
what the four already looked like.

The rail is not a defect. Twenty-six settings sections wrapping onto three rows

body, above the first card, where a filter over the whole page reads as a

**Then the fourth queue item, which was recorded as a rename.**
„`set__section-caption` is one job wearing a section's name — 122 uses, 116 of
them the same `<p>` hint. A rename, one pass." That is a true sentence and it
describes the smallest part of the problem. Grepping for the SHAPE rather than

The interesting property is that every one of them is correct. Tokens
throughout, so `check:colours` passes. Every `var()` resolves, so
`check:tokens` passes. They typecheck, they lint, and the 2 711-frame sweep

different measures including a raw `64ch` where a 68ch token exists, and
forty-eight paragraphs whose class never reset `margin` and were therefore
still carrying the user agent's 1em block margins while their neighbours were
not. Two of the copies were inside `packages/ui` itself — the package whose
entire job is that this does not happen.

So `.nx-hint` now exists and is adopted at 659 call sites over 65 files. A
surface that needs looser prose adds `.nx-hint--prose`. A surface with a real
extra — a widget's own inset, a gap above a status line — keeps its class for
that extra and nothing else.

**The gate, and why this tier has one when the eyebrow still does not.**

The obvious rule is „muted ink plus 13px is a hint". It is wrong, and the
counter-example was already in the tree: `.tasks__archive-toggle` borrows both
on purpose, because it is a disclosure BUTTON in the quiet typographic idiom it
shares with `.set__disclosure`. Five more control rules match by coincidence. A
gate that fired on those would have an allowlist within a month, and an
allowlist is how a rule stops being read.

What broke it open is that **the discriminator was not in the stylesheet at
all.** A class whose every call site is a `<p>` is a paragraph tier, whatever
somebody named it — and that pairing needs no exemptions, because a button is
not a `<p>` and an inline `<span>` is not one either. `check:tiers` reads both
artifacts and fires only where they agree. That is worth keeping as a general
move: when a signature over one artifact is ambiguous, the disambiguator is
often in a second artifact nobody thought to read.

One exclusion, written as a rule rather than as a name: a block that declares
its own `font-family` has said out loud that it is a different tier.
`.elec-sim__readout` is the live case — a `<p>`, muted, 13px, and mono with
tabular figures, because it is the simulator's tick counter and not a sentence.

On its first run against the tree it was written for, it found two the hand
survey had missed: `.elec-sim__readout`, which is what taught it that rule, and
`.note__list-notice`, which was a genuine miss and is folded.

**Its own tests then found three defects in the gate**, which is the whole
argument for a gate having unit tests instead of only a green run:

  * every finding's line number was wrong. The rule regex's `[^{}]+` swallows
    blank lines and blanked comments back to the previous `}`, so `m.index`
    pointed at the top of the comment above the rule — it reported

  * `border-color: var(--nx-text-muted)` contains the ink test as a substring,

the list never shrinks. Both assertions were made to fail before they were

and the derived one reports the missing filename rather than a boolean.

cache, so the tool replays a result computed against the version that no longer

### One binary, three ABIs, and a rule that stops being remembered (2026-09-04)

The task in `STATUS.md` §4 read *„the native ABI dance can be retired — the
measurement is already done"*, with a note underneath saying the one measurement
that mattered had **not** been done: nobody had run v13's prebuild under
Electron. That is the whole of this wave. Everything else followed from the
answer.

**The claim to test.** `better-sqlite3-multiple-ciphers` 12.11.1 resolves a
single `build/Release/better_sqlite3.node` per ABI, and pnpm shares one store
copy between `packages/db` (Node's ABI, for Vitest) and `apps/desktop`
(Electron's). Only one can occupy that file, which is the entire reason
`rebuild-native.mjs` existed and the entire reason `smoke` was forbidden beside
a test run. 13.0.3 ships eight prebuilds named `win32-x64`, `linux-arm64`,
`linuxmusl-x64` and so on — **platform and arch, and no ABI** — and a binary can
only be named that way if the ABI does not matter to it. Which is a hypothesis
about somebody else's build system, not a fact, and the difference is the point.

**The probe.** A scratch directory outside the repo; v13 installed once and not
touched again; a reference database written by the repo's own 12.11.1 with the
exact setup `database.ts` uses — `PRAGMA cipher='sqlcipher'`, then a raw 64-hex
key with no KDF — holding one row of Serbian text. Then the same eleven-line
reader run under three runtimes against that one file.

| runtime | `process.versions.modules` | result |
| --- | --- | --- |
| Node 24.18.0 | 137 | row read, row written, row deleted |
| Electron 43.6.0 | 148 | same |
| Electron 44.2.0 | 149 | same |

`sha256 d4f29082…` before the first run and after the last: identical. One file,
three ABIs — and the cipher question, which SQLite3MultipleCiphers moving
1.x → 2.4.0 could have answered fatally (a changed default scheme version means
every database already on a user's disk stops opening), settled by the same
probe, because the database was written by the old version.

Two small things about the probe are worth keeping. Electron's main process
would not `require("electron")` here: the directory has the `electron` npm
package in its own `node_modules`, and that package's `index.js` exports the
*path to the binary as a string*, so `const { app } = require("electron")` gave
`undefined` and the error pointed at `whenReady`. Nothing about loading a native
addon needs `app`, so the probe stopped asking. And `electron.exe` is a
GUI-subsystem binary on Windows with no attached stdout, so the result goes to a
file the caller reads — the same reason `launch.mjs` has the shape it does.

**What the answer bought.** `rebuild-native.mjs`, `rebuild:electron`,
`rebuild:node`, the flip inside `launch.mjs`, the `process.on("exit")` restore
inside `dist.mjs` — all deleted. And with them the standing rule that `smoke`,
`shots` and `demo` must never run beside a test suite. That rule had already
cost a session: a killed sweep left the binary on the Electron ABI and the db
suite came back with 25 failures about a module version, which reads like a
broken test and is not. It is now unrepresentable rather than remembered, and
the proof is the sequence that used to break — a smoke run, then immediately 68
files and 2 268 db tests, green.

**Three defects in the package that the adoption had to absorb**, none of them
ours and all of them ours to handle:

- v13 still ships a `binding.gyp`. npm's implicit rule turns that into
  `install: node-gyp rebuild` for any package that does not set
  `gypfile: false`; v13 **does** set it and pnpm runs the build regardless. The
  first `pnpm install` therefore failed with `Could not find any Visual Studio
  installation to use` — for a binary already sitting in the tarball. The answer
  is `allowBuilds: false`, written explicitly rather than by omission.
- Its `exports` map is `"." : "./lib/index.js"` with no `types` condition, and
  under `moduleResolution: "bundler"` an exports map REPLACES the `types` field
  instead of supplementing it. TypeScript says so in as many words — *„There are
  types at …/index.d.ts, but this result could not be resolved when respecting
  package.json exports"* — and 75 files import this module. A four-line
  `patches/` entry adds the condition, which is one fix rather than thirteen
  shims in thirteen typecheck projects.
- pnpm writes patches with LF and matches them against the store's LF copy, so
  `patches/** text eol=lf` had to go into `.gitattributes` before the first
  Windows checkout could install. The `licences.json` rule, one directory over,
  for the same reason.

**And then the packaging went wrong in the interesting way.** v13's package is
33 MB: 20 MB of prebuilds and 14 MB of the SQLite3MultipleCiphers amalgamation
it would only need in order to compile one. Excluding the source and the seven
unusable binaries looked like a job for a per-platform `files:` under `win:` and
under `linux:` — and a platform `files` does not refine the root list, it
**replaces** it. Every other pattern stopped applying, electron-builder fell
back to `**/*`, and the build cheerfully produced a **388 MB** installer with
the whole source tree and every devDependency inside the asar. It said nothing.
It never would have.

The fix is one list with electron-builder's own `${platform}-${arch}` macros
inside the pattern — which had to be tested, because a macro that silently fails
to expand removes nothing, and a pattern that matches too much removes the one
binary the app needs. The test was to write the rule inverted on purpose: it
excluded exactly `win32-x64.node` and left the other seven, which proves both
that macros expand in `files` and that ordering does what the docs say. Final
state: the unpacked native module is 16 MB → 2.4 MB and the Windows installer
176 961 170 → 174 532 782 bytes, *smaller* than the v12 build it replaces — and
the baseline is not a controlled one in the new build's favour: it was built on
2026-08-31 from the same 1.2.0 version, before E5's bench existed, so the newer
installer carries more renderer code and is still the smaller file.

**The finding underneath that one is the larger one.** Nothing in this repo had
ever read the packaged artifact back. `smoke` proves the app runs — against
`out/`, which is not what ships. Between `out/` and the installer sits
electron-builder, and a `files` glob that excludes too much produces an app
which starts, paints its unlock screen and throws at the first query, with
`pnpm test`, `pnpm build` and `SMOKE OK` all completely silent about it. The
only detector was a person installing the result. `dist.mjs` now reads
`app.asar.unpacked/…/prebuilds/` and refuses a build whose contents are not
exactly the target's one binary — [[DC-111]], and a gate in the one place it can
live, since it needs an artifact to read.

**A separate defect found on the way out**, recorded because it is the same
shape in a different file. The Makefile's `GATES` list was written by hand, with
a comment defending the choice: a renamed gate would then break loudly instead
of dropping out of `make gates` in silence. Sound argument, wrong failure. Five
gates — `check:address`, `check:quotes`, `check:elec`, `check:controls`,
`check:ids` — had been added to `package.json` and to `ci.yml` and never here,
so `make verify` ran thirteen of eighteen and reported *„all 13 static gates are
green"*: derived, accurate, and about the wrong universe. CI was unaffected
throughout, because CI reads the other list. The list is now read from the
manifest, the way `VERSION` two lines above it already was.

**What is now in front of the founder.** The pin on Electron ^42 has said „do
not bump" for four months on the grounds that 43 has no prebuild for this
module. That is measurably false as of today, and Electron 42 leaves support on
**2026-10-20** — the one thing in this project that gets worse without anyone
touching it. The bump itself is two lines; the work is the `shots` sweep after

by photograph. Recommendation: 44 rather than 43, for the same verification

### The bench that refuses to know what your program does (2026-09-03)

ADR-085's E5 is one table row: *„the deterministic tick, sensor → pin → topic →
actuator"*. Six words of specification for a slice whose name — „simulacija" —
invites exactly the wrong thing.

The wrong thing is easy to name. A simulator that decided a ranger reads 20 cm
when a robot is 20 cm from a wall would be inventing the physics; one that
stopped a motor at that reading would be inventing the control loop. E4 already
had the rule that forbids both — the generators emit the WIRING and never the
behaviour, because *„read the range and stop the motor"* is a decision only the
user has made — and a simulator is where that rule is easiest to break and worst
to break, because a thing that moves gets believed.

So „Klupa" shows the CHAIN, moving, and the chain is entirely fact: for every
board pin that carries a signal, which component is on the other end (from
`boardWiring`), which way the board faces it (from `PIN_FLOW`, one derivation
the whole module shares), which ROS topic the generated package gives it (from
`rosPins`), and — the user's part — whatever waveform they declare on it.

**`rosPins` had to be exported for that, and the export is the interesting
decision.** It was `classify`, private to `ros.ts`. The alternative was for the
bench to name its own topics, which would agree today and disagree the first
time `TOPIC_NAME_LENGTH` or the uniqueness rule moved — and the user would be
reading a topic beside a channel that their own node does not publish on. That
is the contradiction ADR-085 §2 put E3 ahead of E4 and E5 to prevent, in its
most confusing form, so the answer was one derivation with two readers rather
than two derivations that happen to agree.

**Deterministic is load-bearing, not a nicety.** Every value is a closed form of
`(wave, ms)`: no RNG, no integrator, no dependence on the renderer's frame rate.
A run can therefore be scrubbed, replayed and compared; a screenshot of tick 40
is the same picture on every machine; a test asserts a number rather than a
range. And the state an integrator would carry is exactly the state that would
need physics to justify it.

**Two design errors, both caught by writing the arithmetic down.**

The first was `partId` on a channel, resolved through a map keyed by the part's
NAME — and two unlabelled LED diodes are both „LED dioda". The fix was to drop
the field: `RosPin` carries only `part`, the board pin is the row's identity,
and nothing on that screen needed the id.

The second is the better one. `overLogic` — „this line is above what the board
is rated for, at THIS tick" — is the one thing a bench can say that
`rules.ts` cannot, because a static rule answers once for the circuit and this
answers per frame. My first rule took a volts channel's ceiling from the board's
own logic level. Then two facts about the data met: `validateComponent` REQUIRES
`logicVolts` on every board, and **no peripheral in the catalogue declares
`Pin.volts` at all** — it is optional precisely because breakout boards do not
commit to a level. So every analogue channel would have been clamped to exactly
the number it was compared against, and the warning could not have fired on any
circuit anybody can build. Not dead code a reader would notice: a well-typed,
fully-tested flag that is structurally always `false`. The rule now takes the
ceiling from whichever end DRIVES the line — the peripheral on a sensor channel,
the board on an actuator one — and a 3V3 Pi with an analogue sensor on it says
what it should when the reading is dragged to 4 V.

**The tests were written after the code, so they were checked by mutation.**
Three rules flipped one at a time — the sensor ceiling back to the board's, the
digital rounding removed, the unit read from the board pin instead of the
peripheral — and each turned exactly the tests that name it red. A suite that
passes on the first run is a claim about the suite, not about the code.

**A screenshot scene per FORM, not per screen.** The bench's four waveform
shapes draw four different sets of fields behind one `<select>`, and every
channel opens on the one-field shape — so a single scene photographs a quarter
of the surface, which is DC-98's shape exactly. `SET_WAVE_KINDS` cycles the
pickers through all four before the frame, writing through
`HTMLSelectElement.prototype`'s own value setter because React skips a change
event whose value it reads back unchanged.

Deliberately absent, and both for the honesty rule rather than for time: an
instantaneous current model (it would duplicate `current-budget` and invent a
duty→draw curve) and any actuator physics (duty→servo degrees is a convention,
not a fact).

**And then looking at it found six things reading it had not.**

The first is the one worth keeping. Every preview strip drew a flat line along
the bottom of its box — which is correct, a resting channel IS at the floor of
its range — and a stroke centred on the boundary of a `viewBox` has half of
itself clipped away, leaving one pixel sitting on the container's own border.
Every channel opens at rest, so the FIRST thing anyone sees of every preview was
an empty box with a slightly thick edge. On a square wave the asymmetry gave it
away: the top rail at full stroke width, the bottom at half. What makes it a
class rather than an incident is that this tree already knew — `SeriesPlot` has
`PAD_Y = 6` with a comment about exactly this, `FitMeasurements` has
`CHART_PAD = 6` on both axes — and the rule was not carried into a third drawing
because that drawing was small enough to write by hand. DC-107. The fix insets
the VALUE axis only: time genuinely runs edge to edge, because that window wraps
rather than ending.

The second is its twin one layer up, and it took a ramp to see. The strip called
`waveAt` — the shape declared — and the readout beside it called that same value
through `quantize`, which is what the PIN can hold. Those agree to a hundredth on
a percent or volts channel, so every frame taken until this one agreed. On a
digital channel they do not: a declared ramp drew a smooth diagonal twelve pixels
from a number jumping 0 → 1, and the instrument was showing a quantity the
hardware does not have in the same row as the one it does. `channelValueAt` is
the one closed form now, `simulateFrame` and the preview both go through it, and
`waveAt` came off the package barrel so nothing can reach the raw value by
accident. The staircase it draws is truer and also more useful: it tells you what
your own pin will do with that shape at the moment you pick it. DC-108, and worth
reading beside DC-107 — one drawing re-derived geometry the shared chart owned,
the other re-derived a value the model owned, and a bespoke visualisation is
where both live.

The second was the frame itself being of the wrong circuit. „Klupa"'s scene was
written to photograph the rover, which is the only circuit that fills the dialog
— topics, both directions, two of the three units, and the „šta klupa ne prati"
table. What it actually photographed was an UNO with one relay on it. Two scenes
above it switch circuits to reach the sketch and library shapes of „Kod", and the
switcher's choice survives `openModule`; the bench scene had copied „Kod"'s first
scene's reasoning — *„the page opens on the rover, so no preamble is needed"* —
which is true of that scene's POSITION and not of the module. This is DC-77
again, the class that says a step in a sweep must leave the app as it found it,
in the state ELEC persists. So the fix is at the state and not at the reader:
`CLOSE_AND_RESTORE_CIRCUIT` puts the switcher back after every ELEC scene that
moves it, and the two bench scenes additionally name the circuit they need,
because a scene whose subject is one record should say which one.

The third was four strings the dialog never read — and one of them mattered.
Three were column headings for a table that does not exist: the channel list
became cards whose head reads as one sentence, and „Signal", „Vrednost" and
„Tema" stayed behind when it stopped being a table. The fourth was
`waveValuesHint`, the sentence saying a list of readings is separated by
SEMICOLONS — a rule this app invented, because a Serbian decimal comma makes a
comma-separated list ambiguous. Nothing else on the field says so, so a user
typing „0, 1,5" gets one reading and no error. It had been written and never
rendered: half a feature, the exact shape `CLAUDE.md` names for an unused
import. Which raises a question bigger than the slice — roughly 7 700 copy
leaves across 29 string files, and nothing checks that any is read. It is
gateable, but only with a rule that marks a subtree used when anything indexes
its parent, because `s.reasons[row.reason]` uses every leaf and names none.
Recorded in `STATUS.md` as the nineteenth gate rather than built here.

Trimming in the same pass: `simulateRun` and its bound `MAX_TICKS` went, along
with four constants the barrel re-exported. A batch runner over a closed form is
five lines any caller can write, and there was no caller — exported API nobody
imports is the same speculative half-feature in another costume.

The fifth is the one I like least, because the thing that failed was the thing
written to stop exactly this. `SET_WAVE_KINDS` exists because a `<select>` hides
three of four waveform forms from the sweep — DC-98 — and it dealt all four
kinds across the pickers it found. The rover has two channels. So a frame held
two forms, the last two in the list were never drawn, and the one dropped was
„Koraci" — the only shape with a list field and, after the fix above, the only
one carrying a hint. A mitigation written against a known blind spot reads as
complete; its coverage was bounded by the CIRCUIT and not by the helper, and
nothing said so. It takes the shapes to deal now, and two scenes deal two each.

One thing the four sweeps it took to see all this settled on the side: the
maximised frame — the sweep's one photograph whose subject IS the window state —
landed once in four runs. `setSize` was exact for all 2 711 other frames each
time, so it is `maximize()` specifically and intermittently, and the tidy
explanation (a machine with orphaned `electron.exe` on it) died when the run
after the success failed on the same clear machine. The harness refuses to file
a merely-wide window under `maximized/`, so every failing run said so; that
refusal is the only reason one success could be read as evidence. Recorded in
`STATUS.md` with the fix that follows from it — retry three times and then
refuse — rather than a hunt for a window manager's mood.

The fourth came out of the gates rather than the frames. `check:quotes` failed a
full `pnpm test` with *„Test timed out in 5000ms"* and passed on its own in
2.7 s. Nothing was wrong with the gate: Vitest's default budget is a unit test's,
and every gate here walks the entire repository with twenty others doing the
same. A CI runner with fewer cores is that failure with less warning and a
message that names neither the subject nor the cause. `testTimeout: 30_000` in

### The field nobody thinks of as input (2026-09-03)

The ELEC pass had left a line in `STATUS.md` reading *„the archive reader bounds
no `profileId`, in any module"* — a small note about one file, filed under
„none of them urgent". It was neither small nor one file.

The rule that was actually wrong is that **„validated" was being read as a
property of the call rather than of the value.** An identifier is opaque, the app
minted it, and it is „just a key“, so it got `nonEmptyStr(raw.profileId,
"profileId")` in the archive reader and `asNonEmptyString(payload.id, "id")` on
the IPC wire — calls that name the field, throw a typed error, and read exactly
like every real check beside them. What they do not do is ask a question about
the value. That is why nothing caught this: a field with NO check is visible as
an absence, and a field with the wrong check is not.

Nothing downstream helps. Every store writes through prepared statements rather
than through its own validators, and **no migration puts a CHECK on an id column
past `NOT NULL`** — so the reader is the only bound between an archive file and
the database, and the wire is the only bound between a compromised renderer and
the same place. A ten-megabyte `profileId` was a row that landed, that every
later query carried, and that no screen could draw.

**784 call sites**: 146 in `importArchive.ts`, 638 in `main/index.ts`. The count
is the finding. It is also the reason the fix had to be a gate rather than a
sweep — nobody re-reads 784 lines, and the 785th is written next week.

`check:ids` is the eighteenth gate and the first that reads the **AST**. That was
forced twice over. Sixty-nine of the 784 are
`asNonEmptyString(asRecord(payload).profileId, …)`, where „everything up to the
last comma“ stops being decidable without a parser — a regex version of this gate
reported 715 and called the tree clean of the rest. And a text rule would have
fired on `core/src/ids.ts`'s own header, which documents the defect by quoting
it; a rule whose explanation trips it teaches people to stop writing the
explanation.

One constant underneath, `MAX_ID_LENGTH`, at 200: most ids are a 36-character
uuidv7, but a catalogue slug is an id, a registry key is an id, and the dashboard
COMPOSES one — `default:<profile uuid>:<set uuid>:<widget id>`, about a hundred
characters. ELEC's `MAX_ELEC_ID_LENGTH` was the same arithmetic under a local
name, written when the hole looked like ELEC's; it is gone, and `circuit.ts`,
the reader and the wire share the one number.

**Then the same rule, looked at again, produced a second shape.** The reader
validated an attachment's `fileName`, `mime` and `sha256` with the same bare
helper — while `sha256Hex`, exactly the right check, was already in the file and
used two functions away. `RestoreStore` bypasses `NoteAttachmentStore.add`, so
the store's rules (255 trimmed characters, no path separators, a real media type
under 100, 64 lowercase hex) reached an archive only if the reader stated them.
The separator is the one that bites: that name is what the app offers as a
download name, so a `..` in it is a directory traversal the archive proposed
and the user accepted.

### Two clocks and a camera (2026-09-02)

Founder: *„Pushuj, sredi kalendar i sve ostalo sto si nasao, pa kad zavrsis onda
idi dalje, takodje kad pushujes onda CICD mora da bude zelen i sve."* Three
things: push what was ready, close both findings E4c had recorded rather than
fixed, and get the pipeline green. The two findings and the two red jobs turned
out to be four instances of the same question — **what is this instrument
actually looking at, and when?**

#### The calendar clip, and the diagnosis that was wrong

The block is a flex row of a clock and a name, and only the name can shrink, so
a narrow enough column clips the clock against the button's own
`overflow: hidden` with no `text-overflow` to admit it. The fix is a threshold:
`container-type: inline-size` on the block and `@container (max-width: 13ch)`
drops the clock entirely, giving the whole line to the name. Dropping beats
squeezing and beats ellipsising — „08:0…" is a wrong time rather than an absent
one, and in a TIME GRID the block's top edge already states when it starts, so
the clock is a convenience and the name is the content. Above the threshold both
fit by construction and below it there is only one item, which makes the clip
**unrepresentable** rather than merely rarer. `ch` against the block's own
caption font, so the 12-hour label („10:45 PM" is half again as wide as „22:45")
is covered without the threshold being a measurement of one font at one size.

**The diagnosis recorded on 2026-09-01 was wrong, and the correction is the
more useful half.** That entry blamed the fixture: the demo seed places sessions
relative to `Date.now()`, so surely the overlap count drifts through the day. It
does not — `seedDemoFocus` is deterministic for a given date. What drifts is
which elements are AUDITED. `CalendarTimeGrid` scrolls its body to the current
time on mount, and `audit.ts` skips anything more than half hidden by a clipping
ancestor. So the audited set is a function of the scroll position and the scroll
position is a function of the clock: the same defect is visible at 08:00 and
invisible at 15:00. That is **DC-99** — an instrument is not deterministic
merely because its subject is, and a finding that comes and goes usually means
the instrument looked somewhere else, not that the code is flaky.

#### The CI clock: a timeout charged to a lifetime (DC-100)

The `database` job had gone red twice in three days on two unrelated assertions
— „neither endpoint is callable from a browsing context", then „an oversized
body is refused before it is parsed", with a green run between them — each a
`504 !== 400`, each at almost exactly 150 000 ms. Neither failure was about the
endpoint in its message. `supabase/config.toml` never declared `[edge_runtime]`,
so the stack ran the CLI's default `per_worker`, which keeps ONE user worker
alive across requests; the 150-second wall clock is charged to that WORKER, not
to the request. The live suite runs about 160 seconds, so the worker was torn
down mid-suite and whichever call was open at that instant returned 504.
`policy = "oneshot"` gives each request its own worker and its own clock, at the
cost of a cold start this suite should want anyway — every test then meets the
function in the state a deployment does.

A retry in the helper would also have turned the job green, and that is exactly
what makes it the wrong fix: the sentence „this test proves the function refuses
X" would have been false whenever the clock ran out, and silent about it.
Verified green on `743aba5`.

The `Security` job was red for an unrelated reason on the same push: four HIGH
advisories cut against `fast-uri` on one day, all four about the same question —
where a URL points — and all four fixed in 3.1.6. The override moves from
`^3.1.5` to `^3.1.6`. It is `tar`'s and `browserslist`'s mechanism, not
`nanoid`'s: ajv asks for `^3.0.1` and has admitted the patch since it shipped, so
a clean install lands on it by itself; what does not move is the lockfile, since
a resolved version that still satisfies its range is never re-resolved.

### E4c — the machine the circuit is the electronics of (2026-09-01)

Founder, handing the decision back: *„ne znam uradi kako mislis da je najbolje,
mozes i push da urais."* ADR-085 §8 had left the URDF's geometry source open and
said E4 decides; STATUS §5 carried it as the one question blocking this slice.
It is now answered in the ADR itself.

**The answer is (a): a small set of parametric chassis.** Two shapes rather than
the three or four §5 guessed at — `diff-rover` and `four-wheel-rover` — because
those are the two the generator has honest geometry for, and „fixed arm" is a
joint model rather than a chassis. A mesh was rejected for the reason the module
is offline-first at all: it makes the description depend on a file Nexus neither
ships nor can validate, and a mesh whose units or origin are wrong produces a
simulation that runs and is silently wrong. „Both" stays available and is right
only once two shapes turn out too narrow, which nothing has shown yet.

#### Nine numbers, none of them pre-filled

`chassis.ts` is nine measurements in centimetres and grams, and the dialog opens
them EMPTY for a machine that does not exist yet. That is the whole slice's
posture in one detail: Nexus cannot measure a chassis, so a field holding „20"
would be a dimension the user never took, sitting in a file a simulator treats
as measured.

Migration 068 makes the same rule structural rather than encouraged. A TABLE
rather than ten columns on `circuits`, because as columns „half a chassis" is a
legal row and every reader downstream has to decide what a NULL body-length
means — which is how a NULL becomes a default becomes a fabricated dimension. As
a row it is absent or complete, and `NOT NULL` says so. Ten columns on
`circuits` would also be ten columns every query against that table carries
forever for a feature most circuits never use: a breadboard is not a robot.

The one cross-field rule SQL can state is stated: `wheel_track_cm >
wheel_width_cm`, strictly. Wheels centred closer together than they are wide
overlap through the middle of the machine, and wheels exactly touching grind
rather than drive. It is enforced in four places — the dialog (which can explain
itself), main's `asChassis`, the store, and the column CHECK — and each of the
four exists because the one below it cannot say why.

#### A mount is a name, not three coordinates

`circuit_parts.mount` is `front`, `rear`, `left`, `right`, `top` or NULL. The
sensor's origin is derived from the body the user already dimensioned, so the
form never grows three fields per sensor and a chassis edit moves every sensor
with it. Which parts may carry one is a catalogue question and cannot be asked
in SQL, so it stays where `component_id`'s validity already lives.

The URDF's `<sensor>` topics are deliberately NOT the ROS node's GPIO topics,
and the dialog says so in as many words. A `<sensor>` names what a simulator
would publish; E4b's node publishes what a real pin reads. They are two
machines, one simulated and one wired, and a reader who assumed otherwise would
wire a control loop to a topic that does not exist.

No `<plugin>` block is emitted at all. A plugin is what makes a URDF move in a
particular simulator under a particular version, and generating one would be
inventing both.

and no explanation — and an Arduino rover with an HC-SR04 is the single most

#### The half of the slice nobody sees: the archive

`1.41.0`. One new record type and one new optional field, and the reason the
version bump is owed twice over: an older reader would refuse `circuit-chassis`
as unrecognised AND refuse `mount` as an unknown member of a `circuit-part` it
otherwise understands — one baffling line-error per sensor on somebody's robot.

The chassis is the first interchange row keyed on its PARENT: `circuit_id` is
the whole primary key, so the bucket is keyed on `circuitId` and a second

than a silent last-one-wins. `fit-measurement`'s natural-key arrangement, one
module over.

A new table means every place that enumerates tables has to learn about it, and
the sweep is the founder's blast-radius rule applied literally: export, import,

#### Two classes the sweep produced

**DC-94.** Migration 067 gave `circuits` a BEFORE DELETE trigger so that a
cascaded child still leaves a tombstone — once the parent row is gone there is
no `profile_id` anywhere on the path. Migration 068 added a fourth child under
the same parent and inherited none of it: SQLite has no `ALTER TRIGGER`. Every
existing guard passed, because all of them ask „does this table have triggers"
and none can ask „does its parent still know about it". 068 now drops and
recreates `circuits_sync_bd`, and a journal test names the cascade rather than

**DC-95.** `collections.ts` documents its own map in sentences that count it —
„Forty-four of the fifty-four collections", „the eight collections that carry no

three were written true and all three had gone stale (45, 11, 7), and the third
had also stopped listing two of the columns it claimed to enumerate. A count in

#### The sync classification, written down rather than assumed

`circuit_chassis` is a `collection` with `identity: ["circuit_id"]` — the first
one on the map whose parent key IS its identity, which is why `objectId.test.ts`
now pins eleven parented collections instead of ten and says what changed.

Its `wheel_track_cm > wheel_width_cm` is the twelfth coupled CHECK, so it needs
a repair: field-level LWW decides each column alone and two honest edits merge
into a row SQLite refuses to write. The repair honours the newer stamp and the
older gives way to HALF or DOUBLE it — a factor of two rather than the smallest
legal nudge, because a wheel one millimetre narrower than the track reads as a
measurement and this has to read as an artefact. It is the one-millisecond focus
session's choice in this table's units. Doubling stops being a move at 250 cm
(the column's own bound), and there the other direction is taken regardless of
the stamps: producing a legal row is the requirement, honouring the newer edit
is only the preference.

**A caveat worth having written down.** `fields` is right here only because the
WRITER is whole-form: `setChassis` upserts all nine columns on every save, so
every field carries the same stamp and the later save wins the whole machine. If
a partial write is ever added, that classification is what has to change — which
is exactly the kind of thing that is obvious now and invisible in six months.

### E4b — the same circuit, written as a ROS 2 package (2026-09-01)

Founder, still: *„web/sync je za sada trajno na hold-u, dok ne zavrsimo sve
feature za desktop."* ADR-085 §2 scopes E4 as four things — *„Arduino sketch,
ROS 2 package, URDF/SDF, export to disk"*. E4a did the first and the fourth
yesterday; this is the second. The third is blocked on a decision only the
founder can make and stays a question in STATUS §5 rather than a guess.

**The interesting part is not the generator, it is what the generator found.**
Writing a second reader of the same model asked a question the first one had
answered wrongly, and the answer had already shipped.

#### One derivation, two dialects

`packages/core/src/electronics/wiring.ts` is new and is the reason this slice is
small. It answers what a GENERATOR asks — for one board in one circuit, which
of its pins carry signal, what is on the other end of each, which way that pin
faces, and whether the board may speak to it at all — and both generators print
that answer in their own vocabulary. It is `nets.ts`'s argument one level up:
the day two generators derive the same connectivity separately is the day one of
them is wrong about a circuit the other renders correctly.

Nothing in it is platform-specific, deliberately. `BoardWire.direction` is
`"in"`/`"out"` rather than `"INPUT"`/`"OUTPUT"`, because the moment the shared
file spells a word from one platform's dialect the other platform's generator
has to translate back out of it. The sketch's 28 tests stayed green through the
extraction, which is what „behaviour-preserving" has to mean.

It is **not** exported from `@nexus/core`. It is the shape of the answer rather
than the answer, and a caller that reached for it would be a third generator
nobody had noticed writing.

Neither generator is exported either, which is a narrowing this slice made
rather than one it inherited: `generateSketch` was public from E4a because it
was then the only one there was. The barrel now offers `generateCode` and the
two result *types*, and nothing else — the paragraph below about no screen
deciding what a Raspberry Pi is was true only for as long as the barrel did not
let a screen do exactly that.

#### The defect the second reader found (DC-91)

`pwm` is not a direction. On a board's D9 it means „there is a timer behind this
hole"; on a servo's `SIG` or an L298N's `ENA` it means „this input wants a
waveform". One word, two opposite ends — exactly as `i2c-sda` is one word at
both ends of a bus, which is DC-88 from the day before.

Two places had it in a list of things that drive. `sketch.ts` therefore made the
board an **`INPUT`** on a motor-enable line and then printed that floating pin
to the serial monitor as though it were a measurement — a reading of the noise
on a pin the sketch had just refused to drive. `rules.ts`'s hand-kept `DRIVING`
array had the same entry, so `output-conflict` could fire on two servos
paralleled off one line, which is how people parallel two servos.

Fixed where it belongs: `PIN_FLOW`, a **total** `Record<PinFunction, PinFlow>`
with three answers — `drives`, `listens`, and the one that kept being forgotten,
`neither`. Total rather than three arrays for `BUS_ROLE_FUNCTIONS`'s reason: a
twenty-fifth pin function is now a compile error somebody must answer, instead
of a string that belongs to no list and is read as `neither` by one caller and
as a direction by the next. Both call sites read it and the two arrays are gone.

The blast radius reached the **catalogue**. Twelve peripheral pins across
`actuators`, `comms` and `drivers` declared only `["pwm"]` — four servos, a
360° servo, an ESC, a passive buzzer, an IR transmitter, an L298N's two enables,
an L293D's two enables and an IRF520's gate. Under the new rule that reads as
„no direction at all", which is true of the word and false of the part. Each is
now `["digital-in", "pwm"]`, which is what a servo's `SIG` actually is.

#### What the package is, and the four things it refuses

Eight files, the shape `ros2 pkg create --build-type ament_python` makes. Every
board pin a peripheral is really wired to becomes a gpiozero device and a topic:
an input publishes `Bool` on a 10 Hz timer, an output subscribes to `Bool`, a
`pwm` output subscribes to `Float64` clamped to 0–1 (gpiozero raises outside
that range, and an exception in a subscription callback takes the whole node
down — a publisher that sends 1.5 has made a mistake, a node that dies because
of it has made a worse one). There is no control loop, for E4a's reason.

- **A whole package or nothing.** A `wiring.py` with no `setup.py` cannot be
  built, and the user is left writing the ament boilerplate they came here to
  avoid. The two fields that are genuinely theirs — the licence and the
  maintainer's address — are placeholders the generated README names.
- **gpiozero, and no other driver.** The platform's own library, on Raspberry Pi
  OS by default, and working on a Pi 5 where `RPi.GPIO` is not: the same kind of
  fact `Wire.h` was for the sketch. The catalogue's `library` field is **not**
  reused — it holds an *Arduino Library Manager* name, and no rule takes you
  from „DHT sensor library" to a Python package — so a pin whose part declares
  one is left alone and listed, exactly as the sketch leaves it alone.
- **It is not a `rosdep` dependency.** A wrong key in `package.xml` makes
  `rosdep install --from-paths src` fail for the user's *whole workspace*, not
  just for this package. The README gives the apt line instead, which is a fact
  about Debian rather than a claim about rosdistro.
- **Four more pins are listed rather than driven:** an analogue line (gpiozero
  reads high and low, so a level through it is a coin toss the rules engine
  already reports as `analog-signal`), a pin with no derivable direction, a pin
  whose id carries no number and therefore no BCM name, and — as in the sketch —
  bus lines, driver-owned lines and lines more than one part sits on.

Two smaller decisions worth keeping. The circuit's name goes in a `#` comment
line and never in the module docstring, because a name containing three quotes
closes a docstring early. And every `create_publisher`/`create_subscription`
argument is on its own line, always: a topic runs to forty characters, and on
one line a long name puts the call past `ament_flake8`'s ninety-nine columns —
the user's own build turning red over a file they did not write.

**And a gate had to grow, because this slice moved Serbian outside its reach.**
`check:address` read `apps/desktop/src/renderer/src/strings*` and nothing else,
which was the whole of the Serbian copy right up until a generator started
writing a README, a Python docstring and a manifest description into files the
user opens outside Nexus. It now also reads main's native-dialog strings — which
no renderer table can hold, because a native dialog opens before any renderer
exists — and every non-test source under `packages/core/src/electronics/`,
including the catalogue's 153 component summaries, which are read on screen and
had never been checked either. Whole directories rather than named files, on
DC-61's terms: a fourth generator is covered without anyone remembering the line
exists, and scanning an English-only file costs nothing because the gate fires
on Serbian trigger words. Zero findings, which is the answer that was wanted and
not the one that was assumed — the new copy was written under the rule, and now
the rule can see it.

#### The app never chooses

`generateCode` is forty lines and is the door: it reads the board's
`programming` field and routes. A screen that called `generateSketch` directly
would be a screen that had decided a Raspberry Pi gets a `.ino`, which is a

  `source /opt/ros/<distro>/setup.bash` to that file, and a login shell would
  report a correctly configured distribution as unusable because Ubuntu's
  `.bashrc` returns early when `$-` has no `i`. So „Nexus runs `colcon build`" is
  really „Nexus runs `colcon build` in the shell the user configured". Confined
  to the WSL profile — `native` spawns the binary with no shell at all and
  `docker` runs in an image that sources ROS itself. The full argument is the
  amendment to DEV-007.
- **The Docker image is pinned by digest, not by tag**, and the digest is
  `ros:humble-ros-base@sha256:1813d3c8…` — a tag is mutable and this one names a
  program the user's machine will download and run. **The cost is real and is
  owed to the founder in §5**: the pin has no update path, so the day that image
  is withdrawn the profile stops working until a person edits the table.
- **No round against the real thing has happened on this machine.** Nothing here
  has Docker Desktop running with a real image, or a WSL distribution carrying
  ROS. What is verified is the argv the plan produces and the way main drives it;
  what a live engine then does with that argv is exactly the half a green test
  cannot stand in for, and it needs the founder's machine or a CI runner that has
  one.
- **A run that outlives the app is nobody's, and the runner is in-memory only.**
  `dispose()` on quit kills the process and issues the container removal, but a
  process killed by the OS, a crash or a power loss takes that away: the next
  launch shows `idle` with no last outcome, because there is no state on disk to
  reconcile from, and a Docker container that survived is not looked for. It is
  bounded rather than open — `docker run --rm` removes that container when
  `colcon build` finishes, which it does on its own — and the user is not told
  either way. Whether a startup sweep is worth its own probe is in §5.

**What E4's sketch deliberately does NOT do.** It emits the WIRING, never the
program: a named constant per board pin a peripheral is wired to, the `pinMode`
each needs, the bus initialisation the board's own pins call for, and a `loop`
that reads every input back to the serial monitor. „Read the distance and stop
the motor under 20 cm" is a decision only the user has made, and generated code
that invented one would be a guess carrying the authority of code. Three
narrower refusals follow from the same rule: a pin whose part declares a
`library` gets no `pinMode` and no read (a DHT22's DATA line is a timed
protocol, not a direction), an `#include` is written only for `Wire.h` and
`SPI.h` (the catalogue's `library` is a Library Manager *name*, from which a
header filename is not derivable, so the libraries are listed for the user to
install instead), and **no output is ever driven** — a relay closed by a program
nobody wrote is a machine acting for no reason.

**What E4's ROS 2 package deliberately does NOT do**, which is the same
sentence in another dialect. Every board pin a peripheral is really wired to
becomes a gpiozero device and a topic — an input publishes `Bool` on a 10 Hz
timer, an output subscribes to `Bool`, a `pwm` output subscribes to `Float64`
clamped to 0–1 — and the node contains no control loop at all, because *„read
the range and stop the motor"* is a decision only the user has made. Four
narrower choices follow from it:

- **A whole package or nothing.** Eight files, the shape `ros2 pkg create
  --build-type ament_python` makes. A `wiring.py` with no `setup.py` cannot be
  built, and the user is left writing the ament boilerplate they came here to
  avoid. The two fields that are genuinely theirs — the licence and the
  maintainer's address — are placeholders the generated README names.
- **gpiozero, and no other driver.** The platform's own library, present on
  Raspberry Pi OS, and working on a Pi 5 where `RPi.GPIO` is not — the same
  kind of fact `Wire.h` was for the sketch. The catalogue's `library` field is
  **not** reused: it holds an *Arduino Library Manager* name, and no rule takes
  you from that string to a Python package, so a pin whose part declares one is
  left alone and listed exactly as the sketch leaves it alone.
- **It is not declared as a `rosdep` dependency,** deliberately. A wrong key in
  `package.xml` makes `rosdep install --from-paths src` fail for the user's
  *whole workspace*. The README gives the apt line instead, which is a fact
  about Debian rather than a claim about rosdistro.
- **Four more pins are listed rather than driven:** an analogue line (gpiozero
  reads high and low, so a level through it is a coin toss the rules engine
  already reports as `analog-signal`), a pin with no derivable direction, a pin
  whose id carries no number and therefore no BCM name, and — as in the sketch —
  bus lines, driver-owned lines and lines more than one part sits on.

**What E4c's URDF deliberately does NOT do.** It describes the machine's
*geometry and its sensors*, never its behaviour: links for the body and the
wheels, a continuous joint per wheel, a `<sensor>` per part the user bolted to a
named face, and no `<plugin>` block at all. A plugin is what makes a URDF *move*
in a particular simulator under a particular version, and generating one would
be inventing both. Five narrower choices follow from the same rule:

- **Nine numbers the user typed, and none of them pre-filled.** Nexus cannot
  measure a chassis. A form that opened holding „20" would be a dimension the
  user never took, sitting in a file a simulator treats as measured — the same
  refusal the whole ADR-085 §8 answer rests on. The dialog therefore saves nine
  or none, which is what migration 068 makes unrepresentable in the database
  rather than merely discouraged in the form.
- **A mount is a NAME, never three coordinates.** `front`, `rear`, `left`,
  `right`, `top`. The sensor's origin is derived from the body the user already
  dimensioned, so the form never grows three fields per sensor and a chassis
  edit moves every sensor with it.
- **The URDF's sensor topics are not the ROS node's GPIO topics**, and the
  dialog says so. A `<sensor>` names what the simulator would publish
  (`sensor_msgs/msg/Range`, `sensor_msgs/msg/Imu`); E4b's node publishes what a
  real pin reads. The two are different machines — one simulated, one wired —
  and a reader who assumed otherwise would wire a control loop to a topic that
  does not exist.
- **Anything the generator has no honest geometry for is LISTED, not guessed.**
  A sensor with no simulator equivalent, and a sensor the user has not mounted,
  both appear in „Senzori koji nisu u modelu" with the reason. Actuators are
  not listed at all, because the generator walks sensors only — a buzzer is not
  a thing a URDF describes.
- **A measured Arduino is told so, rather than left to notice.** The model is a
  *file of the ROS 2 package*, so a board that gets a sketch gets no model —
  and „Mašina" has already promised the user that their nine numbers go into
  something a simulator reads. „Kod" over a sketch therefore prints „Model
  mašine → Mašina je opisana, ali je skica ne koristi…" whenever the circuit
  has a chassis, and says the measurements stay with the circuit. The absence
  is printed for the same reason the package prints its own: a section that
  disappears is indistinguishable from a feature that broke. The demo profile
  carries one measured Arduino specifically so the sweep can photograph it.

**What E5's bench deliberately does NOT do**, which is the same sentence again
and the place it was easiest to break. „Klupa" runs a clock and shows the chain
the circuit really has, moving: for every board pin that carries a signal, which
component is on the other end, which way the board faces it, which ROS topic the
generated package gives it, and what value is on it at this tick. Everything but
the last comes out of `boardWiring` and `rosPins` — the same two calls the
generators make, which is why `rosPins` is exported rather than re-derived: a
bench naming a topic the user's own node does not publish on is the
contradiction ADR-085 §2 put E3 before E4 and E5 to prevent. **The last one is
the user's.** A simulator that decided a ranger reads 20 cm when a robot is
20 cm from a wall would be inventing the physics *and* the control loop, and
would be believed, because it moves. Five narrower choices follow:

- **Deterministic, with no state at all.** Every value is a closed form of
  `(wave, ms)` — no RNG, no integrator, no dependence on how often the renderer
  calls it. So a run can be scrubbed, replayed and compared, a screenshot of
  tick 40 is the same picture on every machine, and a test asserts a number
  rather than a range. The physics that would justify an integrator is the
  physics the module has refused to invent.
- **The tick is SIMULATED time, and the frame rate is not.** The bench advances
  at a steady ten frames a second whatever the step is set to, so a 1 ms step is
  a slow-motion reading rather than a thousand frames a second, and a 10 s step
  is not a stopped clock. The copy says so, because it is the one thing about
  the transport a reader would otherwise get backwards.
- **Four waveforms, declared per channel:** a constant, a square wave with a
  duty cycle, a sawtooth ramp (a triangle would be two ramps drawn as one, and
  a user reading „5 → 30 cm" would watch it spend half its time going the other
  way), and a list of readings walked through in turn. The list is separated by
  **semicolons**, because the app writes decimals the Serbian way and „1,5" in
  a comma-separated list could be one number or two.
- **It carries an analogue line the ROS package refuses.** `ros.ts` skips one as
  `analog` because gpiozero reads high and low and would publish a coin toss; a
  bench can carry a voltage honestly, so it does — and the row then has no
  topic, which the dialog says out loud rather than leaving to look like a topic
  that failed to render. The other three skips (bus, driver-owned, shared) are
  `BoardWire.owner` verbatim and are listed with their reasons.
- **One warning, and it is the one a static rule cannot give.** `rules.ts`
  answers „are these two parts on incompatible rails" once for the circuit;
  the bench answers „is this line over the line at THIS tick", which is a
  different question the moment a value moves — a 5 V sensor the user never
  drives past 2 V trips the static rule and never trips this one. It is set only
  on a volts channel of a board that states a logic level, and the channel's
  ceiling is taken from whichever end DRIVES the line rather than from the
  board, because a ceiling taken from the board would clamp every reading to the
  very number it is compared against and the warning could not fire on any
  circuit anybody can build. **No instantaneous current model and no actuator
  physics**: the first would duplicate `current-budget` and invent a duty→draw
  curve, and duty→servo degrees is a convention, not a fact.

**The bench stores nothing.** A run is an instrument, like the generated code:
the circuit is what the profile keeps, and closing the dialog leaves exactly the
circuit that was open when it opened. Whether a set of waveforms is eventually
worth a migration is an open question, in §5.

**Six things the eye review of E5 turned up, all fixed in the same pass.**

- **The waveform preview drew its floor ON the box's boundary** (DC-107), so
  the half of the stroke outside the `viewBox` was clipped and the pixel left
  over sat on the container's own border. Every channel opens at rest and rest
  IS the floor, so the first thing the user saw of every preview was an empty
  box with a thick edge; on a square wave the top rail drew at full width and
  the bottom at half. `SIM_PREVIEW_PAD` insets the VALUE axis only — time runs
  edge to edge, because that window wraps rather than ending. The rule was
  already written down twice in this tree (`SeriesPlot`'s `PAD_Y`,
  `FitMeasurements`' `CHART_PAD`) and simply not carried into a third drawing
  that was small enough to write by hand.
- **The strip and the number beside it disagreed** (DC-108). The preview called
  `waveAt` — the shape the user declared — and the readout called it through
  `quantize` — what the pin can hold. On a percent or volts channel those agree
  to a hundredth. On a DIGITAL one they do not: a declared ramp drew a smooth
  diagonal twelve pixels from a number jumping 0 → 1. `channelValueAt` is now the
  one closed form both go through, and `waveAt` is off the package barrel so
  nothing can reach the raw value by accident. The strip draws a digital ramp as
  the staircase it is, which is truer AND more useful — it says what the pin will
  do with that shape at the moment the shape is picked.
- **The sweep photographed the wrong circuit** — DC-77 again, in the state ELEC
  persists. Two of the „Kod" scenes reach their shape by switching circuits and
  the switcher's choice survives `openModule`, so „Klupa" asked for the rover's
  bench and got the UNO the scene above it had selected: one channel, no topic,
  one skipped row, in a frame that looks exactly like a bench. Fixed at the
  state rather than at the reader — `CLOSE_AND_RESTORE_CIRCUIT` puts the
  switcher back on every ELEC scene that moves it — and the two bench scenes
  now also name the circuit they need, because a scene whose subject is one
  record should say which.
- **Four strings the dialog never read**, one of which was load-bearing —
  `waveValuesHint`, the only place saying a list of readings is separated by
  semicolons. It is rendered now; the other three were headings for a table the
  design does not have. The subsystem question it raises has its own section
  below. `simulateRun` and four barrel-only constants went in the same pass:
  exported API with no importer is the same speculative half-feature.
- **The fix for one blind spot had a blind spot of its own.** `SET_WAVE_KINDS`
  exists because a `<select>` hides three of four waveform forms from the sweep
  — DC-98's shape — and it dealt all four kinds across the pickers on screen.
  The demo rover has exactly TWO channels, so a frame holds two forms and the
  last two in the list were never drawn: „Koraci", the only shape with a list
  field and now the only one carrying a hint, was the one dropped. The helper
  now takes the shapes to deal and two scenes deal two each, because the
  coverage is bounded by the circuit and not by the helper. **A mitigation
  written against a known blind spot reads as complete, which is precisely why
  its own bound has to be stated.**
- **`check:quotes` timed out in a full `pnpm test`** and passed alone. Nothing
  was wrong with the gate: Vitest's 5 000 ms default is a unit test's budget,
  and every gate here walks the whole repository with twenty other gates doing
  the same. `vitest.scripts.config.mjs` now sets `testTimeout: 30_000` — a
  tenfold margin on the slowest gate measured, and a failure mode that would
  have surfaced on a CI runner as an unexplained red check.

All three generators read **one** derived model (`wiring.ts`), for `nets.ts`'s
reason: the day two generators derive the same connectivity separately is the
day one of them is wrong about a circuit the other renders correctly. And the
app never chooses between the first two — `generateCode` reads the board's
`programming` field, and main derives from the same call whether the user sees a
file picker or a directory picker, so a renderer cannot ask for the wrong one
because it cannot ask for either. The URDF is not a third choice: it ships
INSIDE the ROS 2 package, at `urdf/<name>.urdf`, because a robot description
with no package around it is a file the user has to find a home for.

**What E3 deliberately does NOT do.** It is a static rules engine, not a
simulator: it reads the topology and the catalogue's declared numbers, so it can
say „this pin drives a 5 V rail into a 3.3 V part" but never „this design draws
740 mA at the third second". `current-budget` sums `typical`, not `peak`, for
the same reason — summing every part's worst case would report a fault on
almost every correct circuit, and a rule that fires on correct work is a rule
the user turns off. Two more limits, both intentional: a **board is exempt from
the supply/ground presence rules** (a UNO has a `VIN` pin and is USB-powered in
nearly every correct circuit, so demanding a wired supply would be wrong more
often than right), and **two pins are judged as crossed only when they are on
the same bus** — the ESP32 remaps I²C at will and software I²C on ordinary GPIO
is normal practice, so different buses at the two ends means one of them is
bit-banging and that is not the rule's business. *That last limit was corrected
on 2026-08-31 (DC-88): it used to exempt only a pin that declares no role at
all, which is a much smaller set than it reads as — every board's bus pin is
also an ordinary GPIO with a second name, so a BMP280 bit-banged onto a UNO's
D11 met `spi-mosi` and was reported as an error.*

**Two smaller things ELEC left open — both closed 2026-09-22.** It had no
`SearchKind`, so circuits were not reachable from Ctrl+K; this file was right
that the gap needed a migration and a backfill rather than a component, and
circuits are the **tenth indexed kind** now (`dad4946`) — the union and its six
Serbian aliases, a rung on `KIND_PRIOR` between a document and a subject,
migration 070's projection view with the closing backfill, the module gate, and
the chips, labels and deep link in the renderer. The palette's chip row now ends
in „Kola" and the search page's facet line reads „Kola 3". And
`.canv__swatch`'s „bez ispune" ×-glyph was the same recipe as
`.note__swatch--none`; both are `.nx-swatch--none` in `@nexus/ui` now
(`86ef2b9`) — which is what the cascade change was waiting for, and the canvas
copy turned out to be applied to its colour tiles as well, where nothing inside
the box reads it. Three surfaces, 21 frames, zero findings.

**The tenth kind cost three findings on the way, all closed rather than noted**
(DC-140, DC-141, DC-142). `nx_fold` was registered by hand in twenty test
helpers and not in the twenty-first — the one written when no migration above 64
used the function, which migration 070 made false; `prepareConnection` is now
