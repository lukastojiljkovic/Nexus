**Wave 37 — second lane (2026-07-31, pushed — SRCH-008's buildable half):**
`f5d2b06` **attachment CONTENT in the search index** (ADR-069, migration
**048**) — no trigger can fill the column (the bytes are encrypted on disk,
outside the database), so main extracts once where it already holds the blob
key and the bytes, and SQL sees only the finished value. `extracted_text`'s
NULL-ness IS the bookkeeping: NULL = never attempted (the candidate set, and
the predicate of the two partial indexes that *are* the pending queue),
non-NULL = attempted whatever came out — so `''` means „we looked, there is
nothing" and covers all three failure modes with no second flag and no
infinite retry. One carve-out: a failure arriving together with a lock is not
marked attempted, because the failure was the lock, not the row. The text
rides `body_folded` (matchable) and deliberately NOT `body` (displayed) —
migration 025's identical-bodies rule broken on purpose, toward honesty: a
snippet must show the RECORD, not a paragraph lifted out of a file it carries
— and that divergence is exactly what lets the surface mark „poklapanje u
sadržaju priloga" instead of showing a row that appears to match nothing.
Migration 048 needs NO re-projection statement (every value is NULL when it
runs, so both widened expressions are byte-identical to the old ones — pinned
by a test that migrates a populated 47-era file). The text does **not** travel
in an archive and needs no version bump (it is derived from bytes that already
travel; a carried copy could disagree with them), and the obligation that
comes with that is met — a bounded backfill runs at unlock and at the end of
restore-apply, import-apply and restore-undo. **Out by name:** PDF/DOCX/XLSX
(they need a parser dependency this repo will not add — scraping byte runs
would put fragments of the wrong words into an index the user must be able to
trust), `subject_attachments` (its file NAMES are not projected either,
migration 035, deliberately — indexing its contents would be a wider feature
wearing this one's clothes), and PRIV by construction. Gates at `f5d2b06`:
typecheck 7/7 forced, core **1969** / db **1515** / desktop **969**, lint 7/7
(3 documented), build 3/3, SMOKE OK (incl. a new leg proving the chain against
the real encrypted blob store), post-smoke db 1515, grep 0. ·
**Wave 37 — first lane (2026-07-31, pushed):** `7eafe8b` **tiered
age thinning of note version history** (ADR-070) — the flat 50-row window
failed in both directions on ordinary use (one hard afternoon evicted the
months behind it; a note edited twice a year kept two checkpoints two years
apart), so density now follows age: everything from the last 24 h, hourly for
a week, daily for a month, weekly beyond, newest-in-bucket wins, and a note's
OLDEST checkpoint is unconditional. The rule is a pure clock-parameterized
function in `@nexus/core` applied in the SAME transaction as the insert; the
cap stays a backstop that COARSENS the schedule rather than truncating its
tail (each rung a strict coarsening, so the answer stays idempotent, and it
deliberately overshoots under the cap). Thinning lives strictly inside
`captureVersion`, so a restore returns a history in exactly its exported
shape; an unparseable `created_at` is never offered to the schedule and so
never deleted; PRIV keeps its own seq-ordered keep-count because `created_at`
is one of only two cleartext facts a sealed version row has and age-thinning
it would be a timing side-channel. Gates at `7eafe8b`: typecheck 7/7 forced,

**Wave 36 — second half (2026-07-31, pushed):** `a004826` **the four PRIV
refinements** (ADR-066) — the sealed **version history** finally has a
surface: `priv:versions` answers the two cleartext facts a version row has,
`priv:version-read` unseals ONE version at its own bound sequence and answers
cleartext for display (exactly what the unlocked editor already receives;
the sealed container never crosses the bridge), and restoring is an EDIT that
checkpoints the live state first — the one operation in a zero-knowledge
store with no recovery is not the one we shipped. **Close capture:** every
write marks the note uncaptured and leaving the surface seals it, which is
what makes it idempotent; the cadence capture deliberately does NOT clear the
mark (it captures what a write REPLACED, so what it leaves live would be
overwritten unrecorded). Ordering is the point — a capture that cannot seal
is a lost capture — so `privCaptureAndLock` seals first and locks in a
`finally`, while `performLock` stays synchronous and unconditional (it is
also the quit and smoke path). **Search** becomes a session index built once
at unlock, dropped at lock, marked stale by restore/undo, answering IDS ONLY,
registered with nothing — private notes stay invisible by construction.
**The orphan sweep** runs only when the one-slot undo can no longer bring
rows back, aborts entirely on any container that will not open (references
live inside the envelopes), and deletes only files this session's blob key
can authenticate — `private-blobs` is per ACCOUNT, so another profile's bytes
are unknowable from here. · `88d330a` **explicit cloze numbering
`{{c1::…}}`** (ADR-068, migration **047**, interchange **1.26.0**) — position
was never identity, and the closed rule ("a deletion's number is its label,
else `position + 1`") is chosen so the implicit reading and the explicit
spelling are the SAME numbering, which is why materializing labels can never
move a card. Repeated numbers are one card with two blanks. Migration 047 is
three `UPDATE`s and never a rebuild (ADR-042's cascade would take the whole
`review_log`), and the note-derived reconcile key rebases in LOCKSTEP with
the ordinal — off the SUFFIX, so it also catches the pre-031 row that is
still `kind='basic'` with a `#0` key — parked in a `#~N` namespace because
`cards_source_block` is UNIQUE and SQLite checks it per row mid-statement.
Era flag `writesClozeNumbers` is the first about a field's MEANING rather
than its absence. Mod-Shift-C assigns max+1, never the lowest unused (reusing
a freed number is the exact swap this prevents); `.apkg` keeps Anki's own
`cN`, which retires `cloze-ordinal-reused` as unreachable. Gates at
`88d330a`: typecheck 7/7 forced, core **1950** / db **1483** / desktop
**953**, lint 7/7 (3 documented), build 3/3, SMOKE OK, post-smoke db 1483,
