# Nexus 3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Nexus 3.0 with the v2.5.1 fixes fully implemented, automatically tested, visually swept, and verified through live interaction.

**Architecture:** Work proceeds in security-sensitive vertical slices. Main owns key material, file reads, pack/ZIM validation, blobs, and model workers; renderers receive typed, bounded views. New behavior is introduced through additive migrations and protocol fields, then dead onboarding and old category paths are removed after the replacement is green.

**Tech Stack:** Electron, React 19, TypeScript, Vitest, SQLite/SQLCipher, Three.js, Transformers.js, pnpm + Turbo.

**Spec:** `docs/superpowers/specs/2026-10-24-nexus-3-design.md`

## Global Constraints

- Working app version begins at `2.5.1`; release version changes to `3.0.0` only after every gate and live check passes.
- Use Luka's configured Git identity; no identity overrides, `Co-Authored-By`, or generated footers.
- Do not create intermediate Git commits, push, open a PR, merge, tag, or publish until the final release task after green verification.
- Private Notes' own passcode remains mandatory and independent of the optional account passcode.
- No plaintext secret or user file path crosses the renderer boundary.
- Linux fallback key material is written only to an owner-only file after setup, and its risk is stated in UI and docs.
- Existing accounts and archives remain readable.
- Every behavior change follows red-green-refactor TDD.
- Public documentation and code are English; Serbian UI copy uses diacritics and gender-neutral wording.
- No fabricated assets, statistics, progress, licences, or source evidence.
- One implementation subagent edits the shared worktree at a time; independent research/review may run in parallel.

## Review Focus

- A Linux user with no keyring creates an account, locks, closes, reopens, and retains data without seeing a Windows-specific refusal.
- A user removes/re-adds the account passcode and Private Notes still requires its own credential throughout.
- Existing blank profile names and hidden default-disabled modules upgrade without a questionnaire and without data loss.
- Cookbook rejects one invalid field with the right message while a valid recipe with quotes, commas, blank time fields, and an empty steps list saves.
- Gallery import fails or is cancelled at each blob/metadata boundary without leaving plaintext, orphan metadata, or a broken thumbnail.
